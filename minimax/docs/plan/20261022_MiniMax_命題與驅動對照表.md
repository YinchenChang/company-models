- 模型：`dist/20261022_MiniMax收支模型_v0_2.xlsx`；Tokenomics 官方快照 v19.0（`1916a06`，SHA-256 `d1728705…970b9d8`，讀取日 2026-10-22）。
- 用途：說明「命題由哪些頁、哪些輸入、經什麼因果方向算出」。數值以 Excel 為準；本表只列結構。ID 為各頁 A 欄 ID。體例比照 `openai/docs/plan/20261008_OpenAI_命題與驅動對照表.md`。

## 1. 一句話命題
**MiniMax 每 MW 算力（實體與 VR 等值）的營收能否覆蓋每 MW 全成本；若不能，缺口何時出現、由誰、以什麼條件補。**（FY2025–FY2030，曆年制，2025 為實際校準年。）
v0.2 新增讀法（跨模型一致，比照 OpenAI v0.6.1）：**回本比值＝營收 ÷（年均上線 MW × 每 MW 年持有成本）**，看年度趨勢，不看絕對數字。

核心輸出：
1. 覆蓋率 `PnL P23`＝每 MW 營收（P21）÷ 每 MW 全成本（P22）。
2. 回本比值 `PxQ X05`；累計需新融資 `Funding F11`、首次需新融資年 `F19`。

## 2. 主因果鏈
```
Tokenomics 快照（TK_Link：IF_TokGW 產能、IF_Util、IF_HoldEcon 持有成本）
SRC_MM（公司財務與市場資料）＋ Inputs（假設，附標記與區間）
        │
Demand：實收單價(I07、M3.1 降價 I30×I31→D09、2027 起 I08) ＋ token 量(2025–26 由營收÷單價推得；2027 起 I09) ──► 計費 token D03
        │
Revenue：企業端＝token × 單價（2026＝1H 實際＋2H ARR 錨 I10）；消費端＝成長路徑(I11、I12) ──► 總營收 R09
        │
Compute：API 推論 MW＝token ÷（每 MW 產能 × η）；η 以 2025 全年、1H26 校準；消費端與訓練 MW＝支出 ÷ 合約價(I02) ──► 總 MW C21
        │
PnL：算力成本＝MW × I02；人事＝人數 × 每人成本；其他＝營收比例 ──► 覆蓋率 P23
PxQ：h＝Σ 世代占比 × IF_HoldEcon；C＝MW × h；比值＝營收 ÷ C（＝實際 m×L ÷ 所需 m×L）
Funding：經調整淨利代營運燒錢 ＋ 預付／自建(I22) ＋ 可轉債 ──► 需新融資 F10、F11
Valuation：股價(S078)×股數 ──► 市值、EV、稀釋、反向檢驗 V13
Checks：K01–K13、CHK_Errors
```

## 4. 與 OpenAI v0.6.1 PxQ 頁的對應與差異
| 項目 | OpenAI | MiniMax |
|---|---|---|
| 每 GW／MW 持有成本 | Σ 世代占比 × `TKQ_IF_HoldEcon` 基準欄 | 同（Hopper＋GB200；v0.1 機隊組合） |
| 平均上線容量 | 官方端點內插＋3 GW 情境 | 模型自身年均 MW（Compute C21；D6） |
| Q | GW × 服務占比 ×（1−免費占比）× 付費產能 × 實際利用率 | API 計費 token（Demand D03；2025–26 由營收÷單價推得） |
| P | TK 有效牌價 `IF_PxEffMix`／`IF_PxEffMix25` | MiniMax 實收單價（TK 有效牌價不適用且不在快照） |
| 比值 | 營收 ÷ 算力成本 | 同 |
| 額外 | 對照列（外部報導支出） | X26–X28：比值∝I02 的結構分解與持平合約價 |
