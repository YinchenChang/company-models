# OpenAI 收支模型 v0.6：命題與驅動對照表（2026-10-08，S6）

- 模型：`model/20261008_OpenAI_v0.6.xlsx`（`model/CURRENT`）；Tokenomics 快照 v5.26（master `3dd1216`）。
- 用途：說明「命題由哪些頁、哪些輸入、經什麼因果方向算出」，供 Andy 與投資處同事審查與追溯。數值以 Excel 為準；本表只列結構。
- 讀法：「→」表示因果方向（左邊決定右邊）；ID 為各頁 A 欄的列 ID，具名範圍以 `等寬字` 表示。

## 1. 一句話命題
**OpenAI 每 VR 等值 GW 的年營收，能否覆蓋每 GW 的年全成本？若不能，缺口要多少外部資金、由誰以什麼條件提供？**（Andy 2026-09-30；FY2025–FY2030，曆年制，2025 為實際校準年。）

命題的兩個核心輸出：
1. 每 VR 等值 GW 差額＝營收 ÷ 供給 VR 等值 GW − 全成本 ÷ 供給 VR 等值 GW（`COST_PropGap_VR`；Cost K83）；覆蓋率 `COST_Coverage`（K85）。
2. 累計外部資金需求（`FND_ExtNeedCum`；Funding F22），及其峰值、首次缺口年（F24、F27）。

## 2. 主因果鏈（正向；反向只作對照）

```
Tokenomics（TK_Link：每 GW token 產能、利用率、持有成本、每 GW 資本支出）
        │
SRC_OAI（公司財務原始數據）＋ Inputs（假設，附標記與區間）
        │
        ▼
Demand：用戶 × 任務 × 每任務 token ──► token 量（DEM_Tok_*）
        │                                   │
        ▼                                   ▼
Revenue：牌價 × 計費 token、ARPU × 人數    Compute：token ÷ 每 GW 產能 × η ──► 有效推論 GW
  ──► 營收總額 − Microsoft 分成＝淨額        合約＋自建 ──► 供給 GW；研發 GW＝供給×(1−閒置) − 推論（殘差）
        │         ▲ 容量上限係數（推論需求 > 推論可用 GW 時截頂）│
        └─────────┴──────────────────────────────────────┘
        ▼
Cost：算力成本（合約實付＋自有資本支出）＋非算力成本（人數 × 每人成本）＋股權報酬
  ──► 每 VR 等值 GW：營收 vs 全成本（命題 1）
        ▼
Funding：自由現金流＝營收淨額 − 算力成本 − 非算力成本（股權報酬加回）
  ──► 期初現金 → 已到位融資 → 外部資金需求（命題 2）

Reverse（管理層營收目標 → 反解所需倍數與反向資金）：只被 Checks 引用，不回饋任何一頁。
Checks：讀取全部各頁，CHK_Errors 必須為 0。
```

## 5. 與 CRWV 模板的關係
- **只借慣例，未共用程式碼**：本模型 builder／engine／測試是自 v0.5 起獨立撰寫（原 repo `YinchenChang/openai-model`，2026-10-07 搬入 `company-models/openai/`），不是 CRWV 模板的副本（`nebius/` 才是）。
- 借用的慣例：①**Excel 為唯一計算引擎**（Python 只產生結構與呈現；HTML 不含計算邏輯）；②**曆年制**（FY2025–FY2030，2025 為校準年）；③**每段報告＋PR 留言**（結論先行、已套用的預設、資料缺口）；④最低現金與來源順序（S7 沿用 CRWV 的資金規則）；⑤成品型式（HTML 一頁摘要＋Excel，放 Drive）。
- 不同處：CRWV 是上市公司以財報與 backlog 為主；本模型以 token 需求 → GW → 成本的物理鏈為主，算力物理一律取自 Tokenomics。
