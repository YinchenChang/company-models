## 0. 命題與架構（不變，供 CC 理解）

- **命題**（Andy 2026-09-30）：OpenAI 每 VR 等值 GW 的營收能否覆蓋每 GW 全成本；若不能，缺口由誰、以什麼條件融資。
- **期間**：FY2025–FY2030，曆年制；2025 為實際校準年。
- **資料分層**（Tokenomics 治理 G1、G8、G9）：
  - 公司財務原始數據（營收、合約、現金、融資輪、人事）→ 本模型 `SRC_OAI` 頁（V5）。
  - AI 技術與算力的原始數據與推導 → 不在本模型重算，一律取自 Tokenomics 的 `SRC_`／`L1_`／`IF_` 名稱（第 P1-3 點的連結頁）。
  - 假設 → `Inputs` 頁藍字，附標記與區間。
- **v0.5 的決定沿用**（D1–D12、N1–N4、S1–S7、R1–R3、V1a、V2a，見 v0.5 JSON 的 `meta.decisions` 與各段 `_note`），除非本工作單第 2 節覆蓋。

## 1. 工程框架（工程類，chat 端定案）

1. **工具鏈沿用 Tokenomics**：`builder/`（Python 產生 Excel）、LibreOffice 重算、`engine/`（pycel）與 parity 測試、CI 分片與快取（直接複製 Tokenomics PR #14 合併後的 workflow 與測試骨架，改為本模型的頁與名稱）。Excel 是事實來源；藍字輸入由 Excel 擁有（只在仍為舊值時才寫）。
2. **CLAUDE.md**：以 Tokenomics CLAUDE.md 修訂五為底，改寫為本模型版本（分工、建置與同步、驗收、報告「預期變動 vs 實際變動」兩張表）。
3. **與 CRWV 模板的關係**：本版採 CRWV 的慣例（Excel 為唯一計算引擎、曆年制、每輪報告寫 `docs/reports/`、報告同時貼 PR comment），但不複製 CRWV 程式碼；與 CRWV 模板的統一（單一設定檔等）留待 CRWV 建置順序中的「分叉 Nebius／Oracle／OpenAI」步驟。若 CC 讀得到 `crwv-model`，報告列出兩者可共用的部分，供之後統一。
4. **Tokenomics 連結方式（快照，不用 Excel 外部連結）**：
   - `TK_Link` 頁：每列一個 Tokenomics 名稱（SRC_／L1_／IF_）、值（藍字，由 builder 從 Tokenomics `model/CURRENT` 讀出寫入）、Tokenomics 版本與提交 SHA、讀取日期。
   - 本模型公式只引用 `TK_` 具名範圍，不直接寫 Tokenomics 數值。
   - 測試：`tools/check_tk_snapshot.py` 讀 Tokenomics master 的 CURRENT，與快照逐名比對；不一致時 CI 報 WARN（不擋合併），報告列出差異。更新快照＝本模型的修補版。
   - **（r1，E1）Tokenomics 尚未提供的名稱**：仍逐名列入 TK_Link，值留空、狀態「待 Tokenomics vN 合併」；`check_tk_snapshot` 報 MISSING（WARN）。不從未合併分支取值。名稱以 Tokenomics 實際名稱為準，報告列出與本工作單暫定名的對照。
   - Tokenomics 下游使用登錄（治理 Stage 3）：報告列出本模型引用的全部 Tokenomics 名稱清單，供 Tokenomics 端登錄。
5. **（r2，E4）分支與 PR**：本 repo 的預設分支是 `main`（不是 master；本檔提到的 master 一律指 Tokenomics）。每個工作包開工即開 PR（可先標 draft），報告全文以 PR comment 張貼，同一份存 `docs/reports/`；chat 端從 Gmail 的 PR 通知讀取報告，只推分支不開 PR 時 chat 端讀不到。
6. **（r2，E5）環境安全**：任何情況不得嘗試 `dangerouslyDisableSandbox` 或其他繞過系統權限的做法。環境錯誤先診斷（缺套件等），無法解決即在報告回報。本條寫入 CLAUDE.md。
7. **版本**：檔名 `YYYYMMDD_OpenAI_v0.6.xlsx`；`model/CURRENT`；每個工作包完成時的檔案為 `v0.6-P1` … `v0.6-P5`（報告與 CHANGELOG 註明），P5 完成即 v0.6。
