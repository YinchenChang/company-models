## 要做的（摘要，細節以 r6 為準）
1. 新增需求與營收頁（英文頁名，例如 `Demand`、`Revenue`；工程類自定）：
   - 訂閱：free／go／plus／pro／seats 各方案用戶數 × ARPU；pro 依 V12／V15 公式；免費用戶只產生 token 需求，不產生營收。
   - 每日任務數 × 每任務 token（付費、免費分開）；需求成長（不含價格）與兩個彈性（任務、每任務 token）。
   - API：層級 top／mid／low × 輸入／輸出 × 單價路徑（`listPriceFYAvg`，2026 依價格事件時點加權）。
   - 廣告：獨立、慢成長的一列（v0.5 決定；不設 FY27→FY30 8 倍那種成長）。
   - 「其他」一列（v0.5 決定）。
2. 營收總額與扣除 Microsoft 分成（`msShare` 20%、上限等，SRC_OAI）後淨額並列；估值與命題用淨額。
3. 輸出：各年 token 量（層級 × 付費／免費），具名範圍供 P3 用；2025 年 token 量與 TK `IF_AllocDemand` 並列（只列差距，不校準）。
4. 驗收：2025 營收對 SRC 實際值的差距（沿用 v0.5 校準方式，列出）；Checks 新增項目取下一個編號並入 registry。
5. **（r5，E8c）價格事件時點 Inputs**，完成後撤除 C27 WARN（編號保留不重用）。
