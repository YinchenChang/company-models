## 結論（先讀這段）
- **2025 營收對 SRC 實際（13.07）的差距＝0**：沿用 v0.5 校準方式，2025 API 是唯一倒推項（實際 − 訂閱 − 廣告 − 其他）。自下而上（API 改用處理 token 2,628T × 單價）則為 14.10，**高 1.03B（+7.9%）**；隱含 2025 API 計費比例 0.80（v0.5 0.70）。
- **2030 淨營收 126.4B**（總額 126.4B；Microsoft 分成 $38B 上限在 2029 用完，2030 分成 0）。2026 總額 34.2B，比 FY2026 獨立推估 32.4B 高 1.8B，比管理層目標 36 低 1.8B；2030 比管理層目標 350 低 224B。
- 與 v0.5 相比：2030 總額 126.4 vs 119.9（+6.5B）。主因是 V12／V15 把 pro 人數下修（訂閱 −2.9B），在 v0.5 校準下 2025 API 倒推值由 3.63 升為 4.15，之後按成長率放大（API +9.4B）。
- 2025 token 合計 3,538T，為 Tokenomics `IF_AllocDemand`（4,190T）的 0.84 倍（口徑不同，只列差距）。
- 價格事件時點 Inputs 已建（E8c），2026 牌價區間由事件時點傳遞；Checks C27 WARN 撤除，編號退役。
- 驗收：parity 49 項全過；LibreOffice 重算錯誤 0；CHK_Errors＝0；範圍外變動（表 2）＝0；TK 快照 OK 62／DIFF 0／MISSING 0。

## 建議後續（不在本段範圍）
- v0.5「API」頁的年度對數歸因（需求量／牌價／組合／價格反應）與「營收彙總」頁的 FY2030 敏感度表（ε 總和 × 牌價年變動）、訂閱「隱含收益率 vs API 等值單價」對照列未移植（屬分析呈現，非需求結構）；建議 S5／S6 視需要補。

## 給 S3 的注意事項
- token 需求輸入：`DEM_Tok_Paid_Top／Mid／Low`、`DEM_Tok_Free_Top／Mid／Low`（各為 Demand!D:I 六格，單位 T＝10^12），合計 `DEM_Tok_Paid`、`DEM_Tok_Free`、`DEM_Tok_Total`；TK `IF_TokGW_*` 單位為 M tok/年 → 用 `INP_254`（T→M 乘數 10^6）換算，不寫常數。

- 營收尚未受容量上限（V1a）截頂：v0.5 以「容量上限係數」乘各營收列；P3 加係數時建議在 Revenue 新增係數列並乘入 R14–R26 的來源或另立截頂後列，保留未截頂值對照。`REV_Gross`、`REV_Net` 目前為未截頂值。
