## 三、系統定義

本模型驗證的精確命題是：

> Anthropic 每 VR 等值 GW 的年營收能否覆蓋每 GW 年全成本；若不能，缺口需要多少外部資金、由誰以何種條件提供。

期間為 2025–2030 年，2025 年作為實際校準年。核心流程為：

1. 使用公司財務與產品數據建立需求。
2. 將需求拆成訂閱、企業席位、API 層級、付費與免費 token。
3. 透過 Tokenomics 產能與 η 校準換算推論／研發 GW。
4. 將逐家合約付款、自建資本支出、非算力成本與股權報酬納入全成本。
5. 計算每 VR 等值 GW 差額。
6. 將總自由現金流與融資流入轉成外部資金需求。

模型合理區分現金與經濟口徑、實體 GW 與 VR 等值 GW、已簽約與條件式／談判中融資、公司揭露與假設／衍生值，以及基準結論與只作對照的 Reverse／OpenAI 連結。

## 八、敏感度先於基準結論

模型的敏感度顯示：

- 單獨把 API 任務數放到低值時，2030 年差額仍為正，但只剩約 +2.1B/GW/年。
- 任務數高值時，2030 年差額可達 +22.9B/GW/年。
- API 任務數低值與價格彈性弱端同時發生，2030 年差額降至 −1.6B/GW/年，覆蓋率約 89%，累計外部資金需求約 9.1B。
- 彈性弱、合約價 20、爬坡一年時，累計外部資金需求約 5.1B。
- 再疊加任務數低值後，外部資金需求增至 77.1B。
- 最差組合下，累計外部資金需求達 178.7B，現金谷底為 −165.3B。

所以「零外部資金需求」是基準路徑結果，不是對整個合理區間都成立。

## 九、Tokenomics v18.0 更新拆解

v5.26 升至 v18.0 後：

- IF_TokGW 各層級產能提高約 1.3–1.8 倍。
- η 由 0.888 降至 0.527。
- 2030 年供給 VR 等值 GW 僅由 8.044 升至 8.067。
- 2026–2030 年每 GW 差額變動均小於約 0.1B。
- 2030 年覆蓋率維持 1.804 倍。
- 累計外部資金需求仍為零。

這證明升版未造成公式斷裂或意外改變結論；但同時顯示 Tokenomics 原始產能上升大部分被 η 反向吸收。η 因而同時扮演 2025 實際支出校準係數、理論產能與供給 GW 間的殘差吸收器，以及 Tokenomics 版本變動的穩定器。它適合作為統合校準值，不應直接解讀為純技術效率。

# Independent Analysis

## 十一、[P] 物理／算力層

優點包括按加速器家族與世代拆分、納入 NVIDIA／TPU／Trainium／AMD、使用 Non-NVIDIA 產出比、分開推論與研發 GW，以及使用 VR 等值避免不同世代 GW 直接相加。

主要限制是 η 以 2025 年單一年校準後固定向前延伸。若模型層級組合、prefill／decode 比例、批次比例、快取命中率、免費／付費 token 結構、非 NVIDIA 機群占比或研發工作負載改變，η 未必維持。故 η 應解讀為「2025 實際支出條件下的統合校準係數」，不宜稱為跨世代通用純效率。

## 十二、[A] 會計與財務層

財務恆等式整體成立：

- 營收淨額＝總營收截頂後扣通路抽成。
- 自由現金流＝營收淨額－算力現金成本－非算力現金成本。
- 全成本另加入股權報酬。
- 年底現金＝期初現金＋自由現金流＋股權流入＋外部資金。
- 外部資金需求補足至最低現金。

但每 GW 損益與公司資金需求不是同一命題。2029 年每 GW 轉正不代表 2029 年不需融資；本模型之所以不需新增融資，主要是 2026 年已到位的 100B 股權資金形成巨大資金墊。報告應避免把「單位經濟轉正」誤讀為「營運自身已供應全部擴張資金」。

## 十三、[I] 誘因與資訊層

- Anthropic 有 IPO 募資與提高估值的誘因。
- 算力供應商有擴大公告合約名目金額的誘因。
- 媒體轉述可能混合 committed、maximum value、option、capacity reservation 與現金付款。
- 競爭對手有低估 Anthropic 淨營收或批評其總額認列的誘因。
- 投資人簡報偏好 run-rate，但財務模型需要認列營收與現金流。

模型已辨識這些誘因。正式輸出仍應把「公司可能不需新增資金」寫成「按目前已到位融資與基準支出路徑，不出現最低現金缺口」。

## 十四、First-best benchmark

一個資料完全透明、資源無限制的強模型應：

1. 從實際付費、免費、快取 token 與分模型層級 token 建立需求。
2. 從實際機群、加速器數量、平均功耗、PUE、模型大小、batch、decode 速度建立物理產能。
3. 不用公司營收或支出反推產能效率。
4. 分開推論、訓練、後訓練、評估與研發叢集。
5. 逐筆連結合約容量、付款、資產所有權與服務起始日。
6. 用實際加速器小時、token 與發票閉合 η。
7. 使用公開 S-1 或經審計財務報表驗證收入、現金與承諾付款。

現版本尚未達到 first-best，原因主要是必要資料未公開，而不是公式不足。

## 十五、同儕與反事實檢驗

任何快速成長且已取得巨額融資的 AI 模型商，在只計已簽合約並假設收入持續快速成長時，都可能得到「早期單位經濟為負、算力部署後成本成長放慢、收入持續成長、後期每 GW 轉正、帳上現金渡過前期缺口」的結果。因此，這部分是產業共同設定，不全是 Anthropic 獨特優勢。

較有辨識力的變數是 API 任務量、有效單價下降、企業／代理型任務留存、每單位算力淨營收、雲端抽成與算力租金，以及新增合約能否帶來等比例營收。

若 2029 年後新增算力合約且供給增加先於需求變現，成本與分母上升可能延後轉正並使現金需求重現；若新增合約源於需求已超過現有供應，則又可能同步增加營收。因此，「不再簽新合約」是維持目前模型結論的條件，不必然是現實世界最優策略。

## 十七、Contradicted

1. **「結論對合理參數區間穩健」不成立。** 需求量與價格反應同時落入不利端即可翻轉 2030 年結論。
2. **「Tokenomics 與需求端已完成閉合」不成立。** TK 自身仍有 6.26 倍 token 帳未閉合，且付費口徑差距明顯。
3. **「2029 年轉正代表資金自給」不成立。** 零新增資金需求高度依賴 2026 年先取得的 100B 融資。

## 十八、Uncertain

1. 2025–2026 年財務數字公開後是否維持。
2. 已簽合約與媒體所稱 maximum commitment 是否同義。
3. 2026 年自建資本支出與報導算力支出是否同口徑。
4. 2029 年後是否不再大量新增算力承諾。
5. η 能否在機群與任務結構變化後維持。
6. API 任務數、每任務 token 與價格彈性的聯合分布。

## 十九、最強反方證據交叉檢驗

最強反方證據不是單一合約對帳差異，而是：模型的 2029–2030 年正差額同時依賴收入高速成長與算力支出停止大幅增加，但現實中高速收入成長往往需要新增容量。

模型以談判中 150B 協議測試部分成本增加，2030 年差額仍為正且不需新增資金；但該情境沒有測試 2029 年後每年追加算力承諾的持續擴張週期。因此，現有情境降低反方疑慮，但未完全消除。

同意模型的計算結構、v0.1.2 升版處理及基準案例結論；不同意將其升格為高信心的 Anthropic 2029 獲利預測，或宣稱已完成 Tokenomics 閉合。

### 情境判斷

- **基準案例：約 50% [Assumed]**：2029 年每 VR 等值 GW 轉正；2026 年融資足以支應至 2030 年。
- **需求／價格不利案例：約 30% [Assumed]**：2030 年接近損益兩平或小幅負值，新增資金需求約 9–77B。
- **持續擴張與多重不利案例：約 20% [Assumed]**：算力承諾持續增加且需求與價格反應落於弱端，資金需求可超過 100B，極端值接近 178.7B。

以上機率為本次研究判斷，不是模型直接輸出。

### 主要驅動變數

1. API 任務數成長率及持續性 [Assumed／Interested-party]。
2. 有效價格下降後的需求彈性 [Analogy／Assumed]。
3. 2029 年後新增算力合約與付款路徑 [Assumed]。

### Load-bearing inputs

- 2026 年 100B 已到位股權融資 [Interested-party／Derived]。
- API 任務數成長 [Assumed，附區間]。
- 價格彈性 [Analogy／Assumed，附區間]。
- 每 GW 合約價 12B [Analogy／Assumed]。
- 2029 年後沒有大量新增基準算力承諾 [Assumed]。
- η=0.527 並向前維持 [Derived]。

結論主要依賴 Assumed、Analogy 與 Derived 值，因此信心不得評為 High。

### 最強反方證據與處理

最弱需求與價格組合足以使 2030 年每 GW 差額轉負，較差聯合情境的外部資金需求可達 178.7B。處理方式不是推翻基準案例，而是把結論改為：

> 基準案例數學成立，但缺乏跨聯合不利情境的穩健性，因此屬條件式可行，不是已證實的結構性獲利。

### 失效條件

出現下列任一可觀測結果時，應重新評估或推翻目前基準結論：

1. 公開 S-1 顯示 2026 年現金、營收、算力付款或融資額與模型差異超過 15–20%。
2. 2027–2028 年 API 任務數成長低於模型低值。
3. 降價後需求彈性不足以抵銷有效單價下降。
4. 2029 年前新增已簽算力承諾超過目前未納入的 150B 情境，且沒有同步新增可變現需求。
5. 重新閉合後 η 或每 GW token 產能差異超過約 25%。
6. 2026 年實際年底現金顯著低於模型的 117.7B。
7. 公開財務資料顯示 2026 年非算力成本高於模型 5–10B 以上。

# 建議事項

## 二十三、版本定位

建議將本版正式狀態設定為：

> **v0.1.2：計算引擎與 TK v18.0 移植通過；研究結論有條件通過；等待公開 S-1 及 token 帳閉合。**

## 二十四、優先改善事項

### Priority 1：建立需求端至算力成本的單一閉合橋接頁

新增「需求端營收公式樹 → token → 推論 GW → 成本」橋接頁，逐層列出 P、Q、付費／免費、模型層級、cache、batch、η 與 GW 的轉換。每一層均應顯示公式、單位、基準／低／高值、標記及來源，並提供橋接差額。

**驗收標準：** TK 與本模型在相同口徑的 Q、付費 token、供給 token、GW 及營收可逐項對帳；未解釋差額單列，不再由 η 靜默吸收。

### Priority 2：拆分 η

至少拆為：

1. 機群技術效率。
2. 利用率／排程效率。
3. 工作負載組合係數。
4. 未解釋殘差。

**驗收標準：** Tokenomics 版本變動只影響應受影響的技術項；未解釋殘差不得因版本升級被動抵銷全部產能變動。

### Priority 3：新增持續擴張情境

除一次性 150B 協議外，新增 2029–2030 年每年增加固定金額或固定 GW 的循環擴張情境，並區分新增供給「無需求」、「部分變現」、「完全變現」。

**驗收標準：** 同時輸出每 GW 差額、公司自由現金流、最低現金缺口、累計融資需求及轉正年度。

### Priority 4：將資金命題拆成三層

分別呈現：

1. 營運自由現金流能否自給。
2. 已到位股權資金是否足以補缺口。
3. 含條件式／談判中融資後是否仍有缺口。

避免「沒有新增外部資金需求」被誤讀為「營運現金流已自給」。

### Priority 5：公開申報後建立 replacement protocol

公開 S-1 或經審計資料出現後，應以正式申報替換媒體轉述，不應在舊值旁直接覆寫而失去版本軌跡。需保留舊值、替換日期、新來源、差異比例、受影響輸出及結論是否翻轉。

## 二十五、最終驗收判定

**正式驗收：有條件通過。**

- 可正式收件：計算引擎、結構、版本移植、基準案例與來源治理。
- 暫不通過：Tokenomics 逐項閉合、跨聯合不利情境的穩健性、高信心 2029 轉正預測。
- 使用限制：所有對外或投資決策用結論均須保留條件式措辭，並明確列出 100B 融資、需求彈性、任務量與未來算力合約等負載性假設。

下一版本達成 Priority 1–3 後，才建議重新評估是否可由「有條件通過」升級為「通過」。
