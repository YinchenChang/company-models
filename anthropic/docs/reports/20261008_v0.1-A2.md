## 結論（先讀這段）
- **2025 校準到實際（差距＝0）**：訂閱 0.79＋API（用量計價）3.80＋其他 0.01＝認列營收 4.60（$B，招股書草稿經 Reuters）。個人付費人數（約 159 萬）、企業席位（約 16 萬）與 API token（746T）都由營收倒推，不另設。
- **2026 半校準＝48.73**（上半年實際 16.23＋下半年持平於 2026-07 年化 65 的一半）。API 為倒推項，隱含 API 任務數為 2025 的 13.5 倍（年增 1,252%）。對照「年化營收 65 → 年底投資人預期 110」推估的 59.0，模型低 17.4%，未達 25% 門檻（無 WARN）。
- **2027–2030 正向推導**：營收總額 81 → 122 → 167 → **215**；扣雲端平台抽成後淨額 74 → 112 → 153 → **197**。企業（席位＋API）占 92–93%，個人訂閱 2030 約 14.7。2027 比管理層 2026-01 版預測（55）高 26；2029 比 148 高 19（只對照，不回饋）。
- **與 OpenAI v0.6 並排**：2025 營收只有 OpenAI 的 35%；2030 淨額為 OpenAI（未截頂淨額 126.4）的 1.56 倍；2030 token 量兩家相近（176k T vs 174k T）。
- **最重要的發現：在目前的彈性假設下，API 營收對牌價不敏感**。任務數彈性 −0.7 加每任務 token 彈性 −0.3（兩者皆沿用 OpenAI v0.6）合計 −1，降價 x% 剛好被用量增加抵銷：牌價年變動從 −15% 改成 0% 或 −35%，2030 營收完全不變，只改變 token 量（2030 −62k T／+251k T），也就是只改變 A3 的算力需求與成本。**2030 營收真正的驅動是 API 任務數成長**（取 OpenAI 同值；上下緣使 2030 淨額 +236／−71），其次是彈性大小（+64／−48）與 2026 半校準基準（+30）。
- 驗收：pytest 54 項全過（parity 情境 19 個 × 2、結構 16 項）；LibreOffice 重算錯誤 0；CHK_Errors＝0、CHK_Warnings＝0；E6 違反 0；OAI_Link 未被計算頁引用；TK 快照比對 OK 86／DIFF 0／MISSING 0；全簿重算 0.15 秒。GitHub CI 因帳號付款／用量上限未啟動（見「CI」）。

## 資料缺口
**找不到**（試過的來源見 SRC yaml `not_found`）：2026-07 之後的 run-rate；官方定價頁原文（擷取被擋，快取倍數與 Batch 折扣用第三方，Analogy）；Opus 4.6 fast mode 價格；模型層級別用量份額（A1 未蒐集；OpenRouter 只有公司份額，本段以 Assumed 區間處理）。
**可能未揭露**：個人付費訂閱數（公司明言不揭露）、官方月活／週活、token 處理量、各方案或席位別人數、企業大單席位價、各雲端夥伴分潤比例（只有 Reuters 推算平均 16%）、Claude Code 2026-02 以後官方 run-rate。

## Tokenomics 缺口
1. NonNV 比例表沒有具名範圍（本段以列標籤＋欄標題讀表；建議 Tokenomics 把 NonNV 比例列進 Interface，例如 `IF_NNV_Out_<族>`）。
2. 每任務 token：Tokenomics 已有（本段改取）；但「訂閱用戶的程式代理任務長度相對 Tokenomics 長程任務」是本模型的 Assumed 倍數（0.15），建議 Tokenomics 提供短程 coding agent 任務檔或 Claude Code 工作階段的量測，以取代倍數。

## TK 快照比對、重算、parity
- `tools/check_tk_snapshot.py`：快照 v5.26 vs Tokenomics CURRENT v5.26：**OK 86**（具名 68＋NonNV 18）、DIFF 0、MISSING 0。
