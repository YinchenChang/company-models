## 1. 分段與並行
- 每完成一個步驟就 commit 並 push，同時覆寫進度檔；任何時候中斷，下一個代理都能從進度檔接手。
- 三家可能同時有代理在工作，其他資料夾也有人在動：**只改自己公司的資料夾**（`amazon/`、`alphabet/` 或 `microsoft/`）。v0.1c 另可改 repo 根目錄 README 表格中自己那一列。`mag/` 只由 chat 端改。
- 例外：v0.1b′（移植）可以**讀** `amazon/` 的檔案並複製到自己的資料夾，不得改 `amazon/`。

## 2. 分支、PR、合併
- 每家一個分支、一個 PR：`claude/amazon-v0.1`、`claude/alphabet-v0.1`、`claude/microsoft-v0.1`（皆自 `claude/mag-setup` 開，已由 chat 端建立並推送）。PR base `main`，標題「<公司> v0.1：整家公司收支與評價模型」。第一張工作單開工時若 PR 不存在就開 draft PR；之後同一分支接續 commit，各張完成時在同一 PR 留言回報。
- 開 PR 用 REST：`gh api repos/YinchenChang/company-models/pulls -f title=... -f head=<分支> -f base=main -F draft=true -f body=...`（GraphQL 不可用）。
- **代理不得合併、不得 force push、不得改 `main`、不得刪除分支或歷史。** 合併由 chat 端審查後處理。
- 推送前先 `git fetch origin <分支>` 並在其上接續；遇 HTTP 413 先 fetch 再推。

## 3. 進度檔（接手用，必做）
- 路徑：`<公司>/docs/reports/20261008_<公司小寫>_進度.md`（同一家各張共用；每張開工時新增自己的段落，不刪其他段落）。
- 最上方「目前狀態」每次 push 前覆寫：**已完成**（含 commit）／**下一步**（具體到下一個代理可以直接動手）／**未解問題**。
- 下方各段「步驟紀錄」表：步驟｜狀態｜commit｜備註。
- 察覺額度或時間快用完：立即停止新工作，先 commit、更新進度檔，push 後結束。

## 4. 資料紀律
- 每一筆數字：數值、單位、期間、來源（文件名稱＋網址）、文件日期、擷取日、標記。
- 標記：[Verified] 可公開查證（經查核的 10-K 財務報表）；[Interested-party] 來源有利害關係（寫明是誰與動機；公司新聞稿、法說、投影片、10-Q 核閱數、新創自報估值）；[Analogy] 由可比對象推估（寫明對象與差異）；[Assumed] 無實證；[Derived] 換算（寫明公式）。Analogy／Assumed 一律給區間。
- **不得杜撰數字。** 找不到就列資料缺口並寫試過哪些來源；「找不到」與「不存在（公司未揭露）」分開寫。
- **SemiAnalysis（含 InferenceX）不可單獨引用**：須有第二個獨立來源，否則只列參考、不作輸入。
- **不以公司自己的數字反推參數**（例如以雲端營收、RPO、AI run-rate ÷ MW 回推每 MW 單價或 k）。每 MW 單價由 Tokenomics × k（k 的證據＝市場價格 ÷ `IF_GPUhrEcon`）；公司數字只作對照或驗證。例外：以「已實現實際數」校準首期期初狀態（MW 或拆分殘差）是允許的，須寫明是校準。
- 同一底層來源的多個呈現（例如 StockAnalysis 與 MarketScreener 都引用 S&P Capital IQ）不算獨立交叉驗證。
- Tokenomics 只透過 `tools/tokenomics/import_tokenomics.py` 產生的版本固定快照取數（只取 `IF_`／`L1_`，下游契約第 2 條）；不得引用 `DC_Cost!`、`Inputs!` 等內部頁。記錄 `model/CURRENT` 檔名與 master 雜湊。
- **公開 repo**：不得放 Andy 的個人情境、先驗、持倉或任何私人資訊。

## 5. 判斷類事項
- 照對照表 r1 第 2、5 節處理，不停下來問；沒涵蓋的判斷，選最保守且最常見的口徑，在進度檔與最終報告「已套用的預設」逐項列出：問題｜採用的預設｜替代選項｜對結果的影響方向（能量化就量化）。

## 6. 停止條件（只有碰到這些才停）
1. 必要的 repo（`YinchenChang/company-models`、`YinchenChang/Tokenomics`）無法讀取或無法推送。
2. 主要一手來源全部無法取得（SEC EDGAR 與公司 IR 網站都拿不到最新季度財報）。
3. 同一個 verify 失敗，經三次實質不同的修正仍無法通過，且原因是模板結構限制。
4. 要讓模型成立，必須做 CRWV 未完成待辦（5a、5b、折舊修正、機率加權目標價、GPU 批次與續約衰退）。
5. 需要改 `main`、force push、刪除分支或歷史、或改自己資料夾以外的檔案。

停下時：commit 並 push、進度檔「未解問題」寫明卡在哪、選項與建議，在 PR 留言（第一行 `[<公司> 回報] v0.1x｜停止｜YYYY-MM-DD`），然後結束。
