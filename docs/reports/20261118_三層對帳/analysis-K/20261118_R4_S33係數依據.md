# R4　2028 年係數 0.8（S33 型係數）的依據

**analysis-K｜2026-11-18｜只讀 repo，未改任何模型**

## 一句結論

**無依據。** 0.8 從來不是校準出來的：它原本是 2026-10-25 三情境框架中「情境 B（平平）＝AI 資本支出消化」的顆數係數，原文就寫「無外部預測可校準，B、C 區間皆 ±0.1」；之後因「基準＝情境 B」的預設（決策 S33、S35）才變成基準係數。repo 內找不到任何歷史「供應鏈原始顆數／產能讀數 ÷ 最終實現出貨」的類比；公開資料中可找到的（2023–2025 年 CoWoS 產能預估）處在缺貨期，方向相反，用了會是牽強類比。所以不給新的低／基準／高。

## 2. 0.8 現在影響什麼

| | 2028 | 2029 |
|---|---|---|
| 原始顆數讀數（供給側） | 52.79 GW | 60.14 GW |
| 現行基準 | 52.79 × 0.80＝**42.23** | 連續法：42.23 × (28.48 ÷ 28.18)＝**42.68** |
| Wattonomics 換算值（需求側） | 28.18 | 28.48 |
| 換算值 ÷ 原始（需求側隱含的「係數」） | 0.534 | 0.474 |

既有區間 0.7／0.8／0.9（原情境 B 的 ±0.1，**同樣是 [Assumed]，不是校準區間**）對基準的機械影響：2028 為 36.95／42.23／47.51 GW；經連續法傳到 2029 為 37.35／42.68／48.01 GW。所以 0.8 不只決定 2028，也決定 2029 的水準。

## 3. 有沒有可用的類比

**問題：** 歷史上「供應鏈原始顆數或產能讀數」相對「最終實現出貨」的比率。

| 候選 | 查證結果 | 採用？ |
|---|---|---|
| repo 內往年 CoWoS／HBM 產能預估對實績 | 沒有。`20261104_v0.13_供給上限與錨定案例.md`、`20261105_HBM供給校準.md` 只有 2026–2029 的當期預估，沒有往年預估與後來實績的配對 | 無資料 |
| 公開的 2023–2025 CoWoS 產能預估 | 這段期間的報導多為產能「連年倍增仍不足」（例：TrendForce 2024-10-21 新聞標題 [CoWoS Capacity Doubles for Two Years, Still Insufficient](https://www.trendforce.com/news/2024/10/21/news-cowos-capacity-doubles-for-two-years-still-insufficient-positive-outlook-for-suppliers/)；我只讀到標題，未讀全文）。那是缺貨期，預估傾向被上修，與「消化期打八折」方向相反 | **不採用**：情境不同，用了會牽強 |

## 4. 結論與建議

- **R4 通過條件「有歷史或外部依據，並給低／基準／高；找不到就明寫無依據」：寫「無依據」。** 0.7／0.8／0.9 是原情境框架的 ±0.1 假設區間，不是依據。
- 不通過條件「只因結果看似合理而保留」：現行保留 0.80 的理由是規則 v1.3「待定年份維持現行」（程序性），不是因為數值合理；這一點本身不違反 R4，但需要讓讀者知道 0.80 背後沒有實證。
- 建議（需 Andy 決定，不在本單內改值）：
  1. 在 `baseline_status.json` 與 Siliconomics Coord 頁的 um28_B 說明欄寫明「來源＝情境 B（AI 資本支出消化）係數；無外部校準；[Assumed]」，避免被讀成有依據的折扣率。
  2. 2027-02-28 期限裁定 2028 待定時，不要把 0.8 當成「兩讀數之間的中間解」的證據；它與需求側隱含的 0.53 相距甚遠，也與原始讀數 1.0 相距 20%，三者都沒有回測支持（見 K1）。
  3. 若要建立類比，可行的做法是**從現在起凍結各版本的遠年原始顆數讀數**，等 2028 年實績出來再算「實現 ÷ 兩年前讀數」——這是唯一不牽強的校準資料，但最早 2029 年初才有。
