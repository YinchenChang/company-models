## 4. 基建延遲情景

需求情景沿用 Siliconomics A／B／C（顆數係數）；延遲情景是**供給側、與需求正交**的第二軸：

| 延遲情景 | 定義（初值，[Assumed]，v0.1 依證據校準） |
|---|---|
| D0 準時 | 公告上線時程照做 |
| D1 基準延遲 | 每一管線階段（動工→完工→併網→上線）延遲取各瓶頸的歷史中位數 |
| D2 嚴重延遲 | 併網與發電機組綁定：一定比例的新 GW 再延 12 個月 |

延遲的傳導：
- **晶片等電：** 出貨顆數不變、上線 GW 延後 → 「已出貨未上線」存量（GW 與 $B）；
- **TK 端：** 閒置期持有成本照付、產能為零 → 每 GW 年營收與回本比值下修（由 OpenAI 等公司模型讀 GW 帳上線路徑計算）；
- **AI半導體 端：** 延遲持續兩季以上 → 後續拉貨減少（D2 下的顆數係數由 GW 帳推出，取代 Siliconomics 目前 2028–29 的 [Assumed] 係數）。

輸出：需求 × 延遲的 3×3 表；對外發布 A-D0、B-D1、C-D2 三條與基準 A-D1。

## 6. 已發現的問題（2026-10-28，供 v0.1 處理）

1. **Siliconomics Deploy 頁的「部署 GW」是成本等值 GW，不是實體 GW。** 公式＝Σ 平台顆數 × 每顆 IT capex ÷ TK 每 GW IT capex（2026 GB300／VR200 混合 33.4〔VR200 占 0.22〕、2027 起 VR200 37.6 $B/GW；2027 起 AMD 改用每顆 100K 的 it_AMDR）。ASIC 的支出被以 NVIDIA 每 GW 成本換算，每 GW 成本較低的 ASIC 會被低估實體 GW。2026 情境 A 為 23.4 GW。[Derived] 拆開看：NVIDIA 三平台 IT capex 595.6 $B → 成本等值 17.8 GW，與以 TK 每 GW 顆數換算的實體 GW（Blackwell 5.4M ÷ 487,008、Rubin 1.7M ÷ 291,744、Hopper 0.5M ÷ 718,048＝17.6 GW）一致；AMD／ASIC 7.6M 顆、186.3 $B（每顆 20–40K）→ 成本等值只有 5.6 GW。若 ASIC 每 GW 成本為 VR200（37.6 $B/GW）的 0.50–0.85 倍（TK NonNV 持有比的範圍：AMD 0.85、OpenAI 客製 0.80、TPU 0.70、Trn 0.61、昇騰 0.55、Maia 0.50；持有比是總持有成本比，借用到 IT capex 是近似），實體 GW 約 5.8–9.9 GW，即 2026 總量可能低估約 0.3–4.3 GW。要等 C2 補上 ASIC 每 GW 顆數才能定案。
2. **單位標籤：** Deploy 頁標「IT 電力」，但除數 `IF_CapexIT` 是「每 TK GW（設施電力）的 IT 資本支出」，結果應為 TK GW（設施）。待 AI半導體 確認後由該專案修改（本專案不改其檔案）。
3. **出貨年＝上線年** 的隱含假設：延遲情景需要把兩者分開。
