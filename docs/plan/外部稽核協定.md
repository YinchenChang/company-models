# 外部稽核協定

- 版本：v1.0（2026-11-20；Andy 2026-11-20 17:09「其他按預設」、J7「檔名和編號應該要調整，不然會衝突誤導」）
- 適用：任何不在本 repo 內作業的稽核者（其他 AI 或人）對本 repo 模型的稽核、複核與試算。
- 相關：排除清單 `docs/plan/個股模型驗收_不需驗收項目.md`；高不確定性預估工作原則 `docs/plan/高不確定性預估工作原則.md`。

## 1. 權威與命名

1. 模型的權威版本只有本 repo `main` 上的成品。版本號（`vX.Y.Z`）與 `Decisions` 頁的決策編號（`S`、`D`、`J` 等）只由本 repo 發出。
2. 稽核者自建的試算檔不得使用 repo 的檔名樣式與版本號。命名：`<稽核者>試算_<模型>_基於<repo版本>_<日期>_t<序號>.xlsx`。試算檔內的決策編號加稽核者前綴（例：`G-01`）。
3. 稽核者的資料夾不得以「現行模型」命名存放試算檔。

## 2. 稽核報告必備欄位

1. 稽核對象的 commit，以及每個被稽核檔案的 SHA-256 或 `build_id`。只寫版本號不足以重現：成品會在版號不變下隨上游重建。
2. 每個數值主張附「工作表！儲存格＝值［公式］」。
3. 涵蓋範圍：讀了什麼、沒讀什麼。「沒查」與「不存在」分開寫。

## 3. 發現分三類

| 類別 | 定義 | 可否給嚴重度 |
|---|---|---|
| 一、已驗證的錯誤 | 可重現的數值或公式錯誤 | 可 |
| 二、與規則衝突的意見 | 與排除清單或已定規則衝突。寫成「建議 Andy 重新考慮〈規則〉」 | 不給；不計入缺陷數 |
| 三、呈現建議 | 不影響數值的標示、版面、警語 | 不給 |

開工前先讀排除清單。第二類不是不能提，是要用對的格式提。

## 4. 試算與意見怎麼進模型

1. 稽核者認為某個權威參數該改時，寫對帳單（Drive `02-AI供應鏈/對帳/`），列證據與標籤。不直接改值後當成新版本。
2. 沒有實證的參數（Assumed、Analogy）不當點值入基準；可以當 Sens 案例提出。
3. 稽核與試算分開交付。同一份文件不同時當稽核報告與模型更新報告。

## 5. 增量

第二次以後的稽核只報增量：新增的發現、已解決的發現、仍未解決的發現各一張表，對照上一份報告的編號。
