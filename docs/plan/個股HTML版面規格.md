**v1.3 優先：** 本檔「v1.3 規格」一節與下方 v1.0–v1.2 內容衝突時，以 v1.3 為準。v1.3 套用範圍：Anthropic、CoreWeave、NVIDIA 三家試作版；其餘個股在 Andy 確認三家試作後，下次改版套用。檢查程式：`tools/company_html/check_layout_v13.py <html>`。

## v1.3 規格（Andy 2026-11-14 08:11）

### A. 章節與順序（每家個股都要有）

| 順序 | 章節（`<section id>`） | 必備 | 圖表 |
|---|---|---|---|
| 頂端 | 投資建議橫幅（`.hero`） | 是 | — |
| 1 | 命題與核心問題（`thesis`） | 是 | 至少 1 張 |
| 2 | 估值（`valuation`） | 是 | 至少 1 張 |
| 3 | 敏感度（`sens`） | 是 | 至少 1 張 |
| 4 | 反向 DCF：現價隱含什麼（`revdcf`） | 是（v1.3 起改必備） | 不需要 |
| 5 | 損益（`pl`）：標準損益表，見 D | 是（取代「三情境損益」） | 至少 1 張 |
| 6 | 驅動因子 → 推導量（`drivers`） | 是 | 至少 1 張 |
| 7 | 個股個別模組（0 到多個；id 自訂） | 依公司 | 每個至少 1 張 |
| 8 | 對帳（`recon`） | 是 | 不需要 |
| 9 | 資料狀態（`status`） | 是 | 不需要 |

個別模組範例：CoreWeave、Oracle 等收支型個股＝「資金缺口與融資（收支模組）」；Anthropic、OpenAI＝「資金」「每 GW 收支」「算力」（原「營收」併入第 5 章損益）。沒有個別模組的公司（如 NVIDIA）第 7 章從缺。頁首目錄（`nav.toc`）順序與上表一致。

### B. 投資建議橫幅文字

- 橫幅下方的文字敘述（`.hero-note` 可見文字）**不超過 200 字**，只講最重點（投資建議的理由、最關鍵的一兩個數字）。
- **不得出現參數名稱**（例：`he_all`、`k_adj`、`p_long`、`od_share`、`u_bill`、`rent_mw` 這類英文代號或底線變數）。需要提到時改用白話（「每 MW 年收入」「隨需占比」）。
- 其餘原本放在橫幅下的說明（邊界揭露、失效情境、方法註記）移到估值章，或收進估值章的摺疊。
- 原則：全頁讀者可見文字（摺疊與附錄以外）都不出現參數代號；檢查程式對橫幅為必過、對全頁為警告。

### C. 命題與核心問題

- 命題照 v1.0（分點、命題回覆摺疊）。
- **重點觀察不超過 5 點，合計不超過 750 字。**
- 本章至少一張圖：回答核心問題最直接的那張（例：CoreWeave 收支關卡逐年現金、NVIDIA 加速器市場與份額）。

### D. 損益（標準損益表）

- **期間：** 歷史 3 年＋未來 5 年（必備）；可加最新一季累計（YTD）或近四季（TTM）作比較欄。未來 5 年用基準情境（B）；情境 A／C 以圖或摺疊表並列。
- **口徑：** GAAP 或 Non-GAAP 依公司主要使用或市場主要使用者而定；表頭**標明「GAAP」或「Non-GAAP」**並一句說明為何用它。
- **列（依序，必備）：** 營收、營收年增率（YoY）、營業成本（COGS）、毛利、毛利率、營業費用、營業利益、營業利益率、其他收入（淨額）、稅前利益、所得稅、稅後淨利、淨利率、EPS（完全稀釋）。
- **比率區（表尾，必備）：** 營收年增率、毛利率、營業利益率、淨利率、淨利年增率。
- 數字一律取自 xlsx；xlsx 沒有的列（例：其他收入淨額、歷史年度）先補進模型的損益頁（`PL` 或等價頁），再由 HTML 讀取。補列不得改變目標價與既有數值格（以逐格比對驗證）。
- 預測期末年模型若只延伸營收與淨利，營業成本、毛利、營業費用以前一年毛利率與營業費用率推算並註明；與延伸期營業利益的差額列核對列，不改既有淨利與目標價（Andy 2026-11-14）。
- 未上市公司（Anthropic）EPS 依模型評價股數計算並註明口徑；無法計算時寫「不適用」並說明。

### E. 驅動因子

- 內容由建置者依命題與重點觀察決定，但**一定要有公司分部營收的推導**（各分部營收怎麼由驅動因子算出、加總為合併營收）。
- 至少一張圖。

### F. 圖表

- 除反向 DCF、對帳、資料狀態三章外，每章至少一張圖（可多張）。圖用共用產生器的 `theme`／`compare`／既有圖型，數字取自 xlsx（v1.2 規則照用）。

### G. 投資建議橫幅與估值章的目標價（Andy 2026-11-14 09:03）

- 橫幅的**現價須附現價日期**（例：「現價（2026-11-11 收盤）」）；未上市者寫價格依據與日期（例：IPO 價格區間中點，招股書日期）。
- 估值章**至少列四個目標價**，並排顯示（表與圖）：
  1. **DCF 目標價**（單純 DCF；失效取 0 者照列 0 並註明）；
  2. **Comparable 目標價**（情境加權；若進加權的是相對倍數調整後值，另列未調整值）；
  3. **加權目標價**（DCF 與 Comparable 加權，即橫幅使用的主值）；
  4. **市場共識目標價**（註明來源、家數與日期；無共識者寫「不適用」並說明，例：未上市）。
- 數字一律取自 xlsx；共識目標價若 xlsx 沒有，先補進 Recon 或 Val 頁（附出處與日期），再由 HTML 讀取；不得改變目標價與評等。

### H. 敏感度主圖（Andy 2026-11-14 09:16；樣板 CoreWeave v5.0.2）

- 敏感度章主圖以**加權目標價相對基準的百分比**呈現：雙向龍捲風圖，輸入取低值、取高值各一張，依影響大小排序，標籤白話（不出現參數代號）。
- 顯示規則照 v1.0：|變動| ≥ 10% 的案例直接顯示，未達者摺疊；全部案例表摺疊。EPS 等其他口徑的敏感度可留作摺疊對照。
- 數字取自 xlsx：Sens 頁若沒有「加權目標價相對基準」欄，先在 Sens 頁新增公式欄（只新增，不改既有格），白話標籤也寫在 xlsx。

## 原則

HTML 是個股模型的展示層，可讀性第一（Andy：「html 是這個個股模型的展示層，所以可讀性是很重要的」）。讀者先看到結論與答案，細節放在可展開的地方。數字一律取自 xlsx（產生器禁止手寫數字），白話文字也用 xlsx 公式帶數字。

## 頁面順序

| 位置 | 內容 | 規格 |
|---|---|---|
| 頁首下方 | **投資建議橫幅**（頂層 `hero`） | 全寬、大字、醒目著色（放空紅、買進青綠、中立金）。並列兩個目標價：**加權目標價**（DCF 與 Comparable 加權）與**只看 Comparable 的目標價**，各附上檔空間；再列現價。投資建議依加權目標價判定，橫幅底部註明五級規則。**自用 AI 讀法 2 的模型**（In 有 `internal_ai_reading`）：目標價格下方加一行（`hero.ai_note`），取 Val 頁 A 欄「橫幅：自用 AI 讀法」列的 B 欄公式字串——讀法 1 目標價與評等、支持現價所需 k、評等翻轉 k（原則第 10 節第 52 條）；主值與兩格目標價不變。缺此列時 `relayout.py` 印警告。 |
| 1. 命題與核心問題 | 命題一句話摘要（頂層 `thesis`）、核心問題 | 命題**分點**（`list` 加 `ordered: true`），不寫成一段。 |
| | **命題回覆**（摺疊） | 緊接在命題清單下方、**預設摺疊**（摘要文字「展開：命題回覆…」）；逐一回答每個命題，答案依模型計算、與命題前後呼應。答案寫在 xlsx README 頁（公式帶數字），格式「問題？答：…」。 |
| | 重點觀察 | **白話**、編號；每點先一句結論，再用數字說明（金額可用「億美元」）。原 README 文字若有下游讀取，保留原列，另設白話列。 |
| 2. 驅動因子 → 推導量 | 情境驅動表（三情境並排）在最上方 | |
| | **依業務性質分塊** | 每個業務一塊（小標「一、…」「二、…」），塊內列該業務用到的參數：**有敏感度區間的參數直接顯示**，其餘固定輸入（實績、公司揭露、換算值）**摺疊**；塊內再以表格分組小標列（`{"sub": …}`）分組。該業務的營運驅動、命題模組、校準與起始值放在同一塊（校準值也依項目分組）。最後一塊放全公司參數（折現率、目標價規則、稅與融資）。In 頁每個參數須剛好歸入一組（建置時檢查，避免漏列）。 |
| 3. 三情境損益 | 現行做法即可 | 說明文字全寬。 |
| 4. 估值 | 說明 → **目標價與現價長條圖** → 結論主要項目 | 結論只列主要項目（加權／DCF／Comparable 目標價、現價、兩個上檔空間、投資建議、情境目標價、市場共識），其餘摺疊。**DCF 折現率（WACC、股權成本、稅後債務成本、RONIC、永續成長率）直接顯示**，緊接在 DCF 彙總之前；組成細項摺疊。DCF 彙總、分部加總各只列約五條主要項目，其餘摺疊；同業倍數摺疊。 |
| 5. 對帳 | 每節只列主要對帳要點 | 其餘摺疊。 |
| 6. 敏感度 | 龍捲風圖只顯示 \|變動\| ≥ 10%（兩位數百分比）的案例 | 未達兩位數者摺疊；全部案例表摺疊。 |
| 7. 資料狀態 | 版本、來源、口徑 | **附錄**（摺疊）：驅動 → 推導對照表、版本要點。 |

全頁說明文字延伸到頁面全寬（頂層 `wide_text: true`）。

## 分區主題圖（v1.2）

依據：Andy 2026-11-11 22:25 看過 Anthropic 新版面後：「有机会用在其他的个股上面吗？像是 NVIDIA 这些，因为他们除了文字、数字以外，还用图表来展示他们重要的一些数据。」22:27「好的，就这样进行吧」；NVIDIA 樣板四張由 Andy 選定，11-12 08:38 認可樣板（「可以」）。

- 每家挑 **2–4 張**主題圖，放在對應章節的**開頭**（驅動、三情境損益、對帳等），回答該章的核心問題；明細表照舊在下方。
- 區塊型別：`theme`（大圖：堆疊／並列長條＋折線，可用右軸）、`compare`（對照長條：模型 vs 指引 vs 共識，每組自有尺度）；用法見 `tools/company_html/README.md`。
- 數字一律取自 xlsx：長條段、點、數值標籤都帶 `data-ref`；堆疊合計取 xlsx 的合計列，不在產生器加總；缺數列時先補進模型，不在設定檔寫數字。
- 列號依標籤找（各公司 `gen_html_json.py` 內），不寫死，避免改版移列後錯位。
- 每張圖附一句圖說，說明長條與線各代表什麼；不寫無法由圖上數字支持的結論。
- 範例：NVIDIA v0.3.6（`nvidia/gen_html_json.py` 的 `_theme_blocks()`）：加速器市場金額與份額（驅動）、營收分部 × 三情境、毛利率 vs HBM 成本占比（損益）、FY2028 模型 vs 指引 vs 共識（對帳）。
- 套用時點：各公司**下次改版**時挑圖套用（S1、S2 照用）；收支型個股（Anthropic、OpenAI）另見 `anthropic/tools/build_html_v2.py` 草稿。

## 改寫既有個股時的做法

1. 在模型建置腳本的 README 頁新增「展示層」段（命題摘要、命題分項、白話重點）與「命題回覆」段，用公式帶數字；原列保留。
2. 改 `<公司>/gen_html_json.py`（或 `html.json` 產生方式）依上表重排；參數分塊依該公司業務性質決定。
3. 版本升一個小版（只改展示層、數值格 0 差異：以「README 以外逐格比對 0 差異」驗證），敏感度不必重跑可沿用。
4. 跑建置腳本全套核對與 `tools/company_html/check_company_html.py`；給讀者看的白話文字、橫幅與命題回覆的數字，由未參與製作的代理對 xlsx 獨立核對。
5. 共用產生器只加可選功能；改動後重建全部公司 HTML，未改版的公司須逐位元組相同。
