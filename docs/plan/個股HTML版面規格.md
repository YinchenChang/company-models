# 個股 HTML 版面規格（展示層）

**版本：** v1.1（2026-11-12；v1.1 加「分區主題圖」，依據 Andy 2026-11-11 22:25–22:27、2026-11-12 08:38 認可 NVIDIA 樣板）；v1.0（2026-11-05）　**依據：** Andy 2026-11-05 18:43–19:25 於算力收支 SpaceX HTML 審閱（五版草稿後定稿）　**範例：** `spacex/`（v0.2.4；`spacex/gen_html_json.py`、`spacex/dist/20261105_SpaceX個股模型_v0.2.4.html`）
**適用：** 所有用 `tools/company_html/` 產生 HTML 的個股模型（算力收支與 AI半導體 兩專案）。**例外：** CoreWeave、Nebius、WhiteFiber 等新雲模板版本維持各自格式（Andy 2026-11-05 19:25），直到依收支型樣板重建為止。**收支型個股**（Oracle v0.5.0 起；Andy 2026-11-10 定為新雲與混合業務公司的樣板）另加可選節 `funding`（資金缺口與融資，緊接命題）與 `revdcf`（反向 DCF，緊接估值），其餘依本規格（Oracle v0.5.1 起）。
**產生器說明：** `tools/company_html/README.md`（區塊型別、格式碼、檢核）。本檔只寫「頁面要長什麼樣」。

## 原則

HTML 是個股模型的展示層，可讀性第一（Andy：「html 是這個個股模型的展示層，所以可讀性是很重要的」）。讀者先看到結論與答案，細節放在可展開的地方。數字一律取自 xlsx（產生器禁止手寫數字），白話文字也用 xlsx 公式帶數字。

## 頁面順序

| 位置 | 內容 | 規格 |
|---|---|---|
| 頁首下方 | **投資建議橫幅**（頂層 `hero`） | 全寬、大字、醒目著色（放空紅、買進青綠、中立金）。並列兩個目標價：**加權目標價**（DCF 與 Comparable 加權）與**只看 Comparable 的目標價**，各附上檔空間；再列現價。投資建議依加權目標價判定，橫幅底部註明五級規則。 |
| 1. 命題與核心問題 | 命題一句話摘要（頂層 `thesis`）、核心問題 | 命題**分點**（`list` 加 `ordered: true`），不寫成一段。 |
| | **命題回覆**（摺疊） | 緊接在命題清單下方、**預設摺疊**（摘要文字「展開：命題回覆…」）；逐一回答每個命題，答案依模型計算、與命題前後呼應。答案寫在 xlsx README 頁（公式帶數字），格式「問題？答：…」。 |
| | 重點觀察 | **白話**、編號；每點先一句結論，再用數字說明（金額可用「億美元」）。原 README 文字若有下游讀取，保留原列，另設白話列。 |
| 2. 驅動因子 → 推導量 | 情境驅動表（三情境並排）在最上方 | |
| | **依業務性質分塊** | 每個業務一塊（小標「一、…」「二、…」），塊內列該業務用到的參數：**有敏感度區間的參數直接顯示**，其餘固定輸入（實績、公司揭露、換算值）**摺疊**；塊內再以表格分組小標列（`{"sub": …}`）分組。該業務的營運驅動、命題模組、校準與起始值放在同一塊（校準值也依項目分組）。最後一塊放全公司參數（折現率、目標價規則、稅與融資）。In 頁每個參數須剛好歸入一組（建置時檢查，避免漏列）。 |
| 3. 三情境損益 | 現行做法即可 | 說明文字全寬。 |
| 4. 估值 | 說明 → **目標價與現價長條圖** → 結論主要項目 | 結論只列主要項目（加權／DCF／Comparable 目標價、現價、兩個上檔空間、投資建議、情境目標價、市場共識），其餘摺疊。**DCF 折現率（WACC、股權成本、稅後債務成本、RONIC、永續成長率）直接顯示**，緊接在 DCF 彙總之前；組成細項摺疊。DCF 彙總、分部加總各只列約五條主要項目，其餘摺疊；同業倍數摺疊。 |
| 5. 對帳 | 每節只列主要對帳要點 | 其餘摺疊。 |
| 6. 敏感度 | 龍捲風圖只顯示 \|變動\| ≥ 10%（兩位數百分比）的案例 | 未達兩位數者摺疊；全部案例表摺疊。 |
| 7. 資料狀態 | 版本、來源、口徑 | **附錄**（摺疊）：驅動 → 推導對照表、版本要點。 |

全頁說明文字延伸到頁面全寬（頂層 `wide_text: true`）。

## 分區主題圖（v1.1）

依據：Andy 2026-11-11 22:25 看過 Anthropic 新版面後：「有机会用在其他的个股上面吗？像是 NVIDIA 这些，因为他们除了文字、数字以外，还用图表来展示他们重要的一些数据。」22:27「好的，就这样进行吧」；NVIDIA 樣板四張由 Andy 選定，11-12 08:38 認可樣板（「可以」）。

- 每家挑 **2–4 張**主題圖，放在對應章節的**開頭**（驅動、三情境損益、對帳等），回答該章的核心問題；明細表照舊在下方。
- 區塊型別：`theme`（大圖：堆疊／並列長條＋折線，可用右軸）、`compare`（對照長條：模型 vs 指引 vs 共識，每組自有尺度）；用法見 `tools/company_html/README.md`。
- 數字一律取自 xlsx：長條段、點、數值標籤都帶 `data-ref`；堆疊合計取 xlsx 的合計列，不在產生器加總；缺數列時先補進模型，不在設定檔寫數字。
- 列號依標籤找（各公司 `gen_html_json.py` 內），不寫死，避免改版移列後錯位。
- 每張圖附一句圖說，說明長條與線各代表什麼；不寫無法由圖上數字支持的結論。
- 範例：NVIDIA v0.3.6（`nvidia/gen_html_json.py` 的 `_theme_blocks()`）：加速器市場金額與份額（驅動）、營收分部 × 三情境、毛利率 vs HBM 成本占比（損益）、FY2028 模型 vs 指引 vs 共識（對帳）。
- 套用時點：各公司**下次改版**時挑圖套用（S1、S2 照用）；收支型個股（Anthropic、OpenAI）另見 `anthropic/tools/build_html_v2.py` 草稿。

## 改寫既有個股時的做法

1. 在模型建置腳本的 README 頁新增「展示層」段（命題摘要、命題分項、白話重點）與「命題回覆」段，用公式帶數字；原列保留。
2. 改 `<公司>/gen_html_json.py`（或 `html.json` 產生方式）依上表重排；參數分塊依該公司業務性質決定。
3. 版本升一個小版（只改展示層、數值格 0 差異：以「README 以外逐格比對 0 差異」驗證），敏感度不必重跑可沿用。
4. 跑建置腳本全套核對與 `tools/company_html/check_company_html.py`；給讀者看的白話文字、橫幅與命題回覆的數字，由未參與製作的代理對 xlsx 獨立核對。
5. 共用產生器只加可選功能；改動後重建全部公司 HTML，未改版的公司須逐位元組相同。
