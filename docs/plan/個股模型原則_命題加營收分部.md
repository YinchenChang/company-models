# 個股模型原則：主要命題＋營收分部 → 損益表（固定規格）

**來源：** Andy 2026-10-27 13:44（AI 投資地圖串）。原話摘錄：

> 不是每個公司的模型都是收支模型，請將公司檔案裡的收支模型更名為個股模型。
> 每個公司的個股模型要依據其主要命題與公司主要業務或營收組成的特性分別建模：每個個股可依其主要命題去建模，再配合其營收組成（主要依據公司的營收部門劃分，如：Nvidia 就分成 Data Center, Gaming, Professional, AD & Robotics）形成最終的 IS 模型，這樣才能與公司和市場口徑有一致的比較基礎。
> 例如：Microsoft 與 Alphabet 用了 CoreWeave 的模型架構，可是其主要營收組成並非算力出租。要依據兩公司自身的主要命題與主要營收來建立自身的模型。
> 請檢查每一檔個股的模型是否符合上述原則。沒有的個股請重新依據上述原則重新建模。

本規格適用 company-models 內所有上市公司模型（算力收支與 AI半導體 兩個 Project 的模型）。未上市模型商（OpenAI、Anthropic）以「營收組成」第 2 條的替代口徑處理。

## 1. 名稱
- 網站與文件一律稱「**個股模型**」。「收支模型」只指以融資缺口、資金瀑布為主軸的模組（例如 CoreWeave、Nebius 的融資頁），不再當作整個模型的名稱。
- 成品檔名：新建或改版時改為 `<日期>_<公司>個股模型_v<版本>`；舊檔名在下一次改版時一併更正，不為改名單獨升版。

## 2. 結構（三層，由上而下）
1. **命題模組**：這家公司被市場定價的核心問題，用可觀察的實體或市場驅動因子正向推導（例：NVIDIA 加速器顆數 × 每顆售價；Microsoft Azure 的 AI 在役 MW × 每 MW 收入；台達電 部署 GW × 每 kW 電源內容 × 份額）。命題模組只驅動它所屬的營收分部（或分部中的一條產品線），不得取代整家公司的營收結構。
2. **營收分部層**：營收列＝公司**官方報告分部**（10-K／年報的應報導部門）；公司在財報新聞稿或法說會固定揭露、市場普遍用來比較的更細產品線（例：Microsoft 八條產品線、Alphabet 的 Search／YouTube／Network／Subscriptions／Cloud、台積電 按平台）可作為分部之下的子列。
   - 每個分部都有自己的驅動因子（命題模組、量 × 價、或有依據的成長路徑），並寫明依據與標記。
   - 命題需要的拆分（例如 AI／非 AI）只能是**某個官方分部之下的子列**，子列合計必須等於該分部；不得用「AI＋非 AI 殘差」取代官方分部。
   - 公司改編分部時，以新分部為主列，舊分部列對照（附重編期間與公告）。
3. **損益表**：分部營收 → 合併營收；有揭露分部營業利益者，由分部營業利益（或分部利益率）加總到合併營業利益，再到業外、稅、淨利、EPS。資本支出、折舊、自由現金流、股東回饋與融資接在損益表之後。

## 3. 必備檢查（每個模型都要有，核對程式會讀）
- **分部對帳**：歷史期（至少最近一個完整會計年度與最近四季）各分部營收＝公司揭露值、分部合計＝合併營收，差額列在核對列且應為 0（四捨五入誤差另註）。
- **口徑對照**：Recon 頁逐分部對照市場共識或公司指引（有則列，無則寫「未找到」）。
- **分部宣告檔**：每個模型資料夾放 `segments.json`，記錄官方分部（名稱、來源文件、日期、最近年度值）與模型 PL 頁對應的列標籤；`tools/segment_check/check_segments.py` 檢查 (a) 每個官方分部在 PL 頁都有列、(b) 分部合計核對列為 0、(c) 標記為命題子列者合計等於母分部。

## 4. 評價
- 各分部可用不同倍數（分部加總，SOTP），並與 DCF 並列；兩者權重是判斷題（預設：DCF 50%＋分部加總 50%，與 AI半導體 v2「DCF＋Comparable 各半」一致，Comparable 在分部層做）。DCF 一律用標準 FCFF 版（NOPAT＋折舊 − 資本支出 − 營運資金增加，明確期到 FY2032，WACC 折現），規格見 `docs/plan/個股DCF標準規格.md`（Andy 2026-11-05）。
- 網站評等仍用五級（強力買進、買進、中立、放空、強力放空）與收支關卡。

## 5. 未上市模型商（OpenAI、Anthropic）與 neocloud
- 未上市公司沒有報告分部：營收列用公司或可信媒體揭露的營收組成（消費訂閱、企業／API、其他），命題模組（算力 MW、token 量價）驅動對應組成；無揭露者寫「本專案未建立」並說明替代。
- neocloud（CoreWeave、Nebius、WhiteFiber）與 Oracle：命題模組本來就是算力出租；仍須依官方分部或營收線列示（例：Oracle 四條營收線、WhiteFiber 雲端服務／託管），融資瀑布保留為「收支」模組。
- **收支型個股樣板（Andy 2026-11-10）：** 「Oracle當樣板的好處是，他除了新雲業務以外還有統SaaS業務，所以還可以用在具有混和業務的公司，如:SpaceX」「另外也請補上反向DCF」。Oracle v0.5.0 起為樣板：在命題＋分部架構之上加收支模組（Fund 來源／用途／缺口／瀑布、RPO 同口徑排程檢查、Sites、Debt 逐檔與到期表、Lease）、反向 DCF（一次動一個驅動整本重算反解）與資金缺口壓力表；收支模組全部引用 CF 頁，模型只留一組現金數字。新雲三家重建時沿用（實作 `oracle/funding_v05.py`）。

## 6. 為什麼（寫給讀者）
同一個模型要能和公司財報、市場共識逐列比較，才知道我們和市場差在哪一條業務。命題只回答「市場在爭論什麼」，分部才回答「錢從哪裡來」。只有命題、沒有分部的模型，會把命題以外的業務壓成一條成長率，評價時看不出差異來源；Microsoft、Alphabet 舊版（v0.2.x）就是例子：三家目標價都偏低且容量越大越低，部分來自口徑而非公司（對照表 r1 C16）。

## 8. In 頁與 HTML 輸入表：「敏感度低／高」與「情境 A／B／C」分開（Andy 2026-10-29 14:26 同意、15:03 指示套用到所有適用的個股）
起因：Andy 讀 Microsoft HTML 時問「主要輸入已有低、基準、高，為何還有情境 A、B、C？」兩者用途不同卻混放在同一張表。
- **適用：** In 頁有「低／基準／高」三欄、且有情境專屬列的模型。情境專屬列＝(a) 鍵名含獨立的情境字母且有同族兄弟（例如 `tp_wA`／`tp_wB`、`cqA_13`／`cqB_13`、`dA`／`dC`、`pace_A`／`pace_C`），或 (b) 項目文字以「情境 A：」「情境 A（…）：」開頭、含「（情境 A）」「情境權重 A」（只有單一情境的列，如 `gm_adj_C28`）。只在其他文字中提到情境（如「收斂法情境 B 的 FY2032 營收年增」「台達電模型，情境 A」）不算。逐期的情境列（例如各季合約價 A／B／C）可在對照中一期一列。
- **In 頁 D／F 欄名改「敏感度低」「敏感度高」**，A1 說明寫明：基準欄 E 進主模型；D／F 只用於 Sens 頁（一次動一個參數），不進目標價。
- **In 頁最後一節「情境驅動對照」**（A 欄文字含「情境驅動對照」）：下一列表頭 D／E／F＝情境 A（樂觀）／B（基準）／C（保守）；每列一個情境驅動，三欄並排，每格 `=E<列>` 只引用上方輸入列（修改仍改上方藍字），H 欄寫「引用 In 頁 k1／k2／k3；說明」；情境 B 無專屬輸入時填常數 0 並說明；情境 A 或 C 無專屬輸入時也可填常數 0，H 欄須寫「情境 A 無專屬輸入列」或「情境 C 無專屬輸入列」（2026-10-30 放寬，AI半導體 請求）。只帶「（情境 A）」字樣的上游模型參考值，不是本模型的情境驅動時，在該列說明欄寫「非本模型情境驅動」即不列入對照（同族兄弟鍵不適用此例外）。對照列 D／E／F 只能是 `=E<列>` 或數字常數，且引用列的情境字母須與所在欄一致（D＝A、E＝B、F＝C）。最後一列情境權重，鍵 `scn_w`，合計＝1。上方**所有**情境專屬輸入列都要列入。本節純展示，不得被其他公式引用。
- **情境值不得直接讀敏感度欄：** 主模型（Sens、Recon 以外各頁）的公式不得讀 In 頁 D／F 欄（含任何指向 D／F 的定義名稱，例如 `*_lo`／`*_hi`、`RHI_*`、`GUHI_*`）來當情境 A／C 的值；應拆成情境專屬列（例：`g27_A`／`g27_B`／`g27_C`，各自有基準值）並列入情境驅動對照，D／F 只留給 Sens。共識區間、舊版對照等非主模型用途可保留，於模型 README 說明。核對程式第 5 項列為警告（暫不判失敗）。
- **HTML「驅動因子」一節分兩張表：**「情境驅動（三情境並排，進加權目標價）」與「單一參數區間（敏感度低／基準／敏感度高；只用於敏感度頁、不進目標價）」，不混放。
- **核對：** `tools/in_layout/check_in_layout.py <成品 xlsx>`（不符即失敗；建置腳本必跑）：欄名、表頭、公式引用的鍵、所有情境專屬列皆列入、權重合計、本節未被任何公式或定義名稱引用；`--all` 掃描全 repo 只報告。
- **改版方式：** 只動呈現，數值不得改變——新舊兩本逐格比對，只有 In 頁 A1、D3、F3 與新增一節不同；版本升一個小版號。
- 已套用：Microsoft v0.3.2、Alphabet v0.3.2（#237）、Oracle v0.4.1；Amazon v0.3.1 由 10-31 排程照做（工作單 `mag/docs/workorders/20261029_MAG_v0.3.1_季度滾動_2026Q3.md` 第 3 節）。CoreWeave、Nebius、WhiteFiber（舊模板，無 In 頁三欄）於下次依本原則重建時套用；OpenAI、Anthropic、MiniMax、智譜的 Inputs 無情境專屬列，不適用。AI半導體 Project 的模型由該專案依本節排入（經 `交流/` 通知）。

## 9. 敏感度覆蓋：In 頁有低／高區間的鍵都要有 Sens 案例（2026-10-30 起）
起因：2026-10-30 Meta v0.1 與 SpaceX v0.1 的獨立核對都發現 In 頁有低／高區間的鍵沒有對應 Sens 案例；其中 Tokenomics 每 MW 持有成本（IF_HoldEcon，鍵 `he_h`／`he_b2`／`he_b3`／`he_vr`）在讀法 2 下影響最大——Meta 低端 765.00（評等跨到中立）、SpaceX 目標價 −38%～+99%——卻完全沒出現在龍捲風。兩案修正後以「四世代同時」一案涵蓋。
- **待涵蓋的鍵：** In 頁（「情境驅動對照」以上）每個 D（敏感度低）或 F（敏感度高）有數值、且與 E（基準）不同的鍵。
- **案例：** Sens 頁表頭＝前 40 列中第一個至少三格非空、且有「…目標價」欄名的列（找不到即失敗）；案例列＝表頭以下、在「…目標價」欄有數值、且 A 欄不是「讀法：」「註：」「說明：」「備註：」「檢查：」（開頭字後接冒號）的列（到「敏感度「…」」逐案明細區為止）。註記列不是案例；「讀法 1（自用 AI 只計成本）」這類真案例照算。
- **涵蓋：** 某案例列的「鍵」欄（表頭以「鍵」開頭）含該鍵，或該列 A、B 欄（驅動、設定）以獨立識別字寫出該鍵（例：「在建工程不另增 MW（cip_ai＝0）」「同時改 tpu_cf」）。A、B 欄以「，；。（）」切子句，含「不變／不改／維持／另見／不重解」的子句裡的鍵不算（例：「WACC +1pt（beta 不變）」不算涵蓋 beta；「同時改 tpu_cf；pace 不重解」算 tpu_cf、不算 pace）。說明欄或其他案例的說明提到的鍵不算（例：WACC 案說明「beta 維持基準不變」）。只有單邊（低或高）案例亦算涵蓋。
- **鍵欄：** 新模型的 Sens 頁一律設「鍵」欄；建置腳本以 `--require-keycol` 呼叫核對（沒有鍵欄即失敗；Meta、SpaceX 已加）。舊模型於下次改版補上。
- **群組：** 同一來源、同時變動才有意義的鍵以一案涵蓋整組。**IF_HoldEcon 四世代**（`he_h`／`he_b2`／`he_b3`／`he_vr`；亦認 Oracle 寫法 `he_h100` 等、`tk_hold_*` 與項目文字「IF_HoldEcon｜」）必須有一個案例列的「鍵」欄寫 `he_all` 或寫出全部有區間的成員鍵——**只認鍵欄**，A、B 欄與說明欄文字一律不算（例：鍵欄 he_b3、A 欄「其餘 he_h、he_b2、he_vr 照舊」不算）；沒有鍵欄的舊 Sens 頁只認 A、B 欄明寫識別字 `he_all`；該列不得含否定字（待補、尚未、未定、未做、未列、不得、缺少、缺案例；「未來」「缺口」不算否定）。只動單一世代、或只在註記寫「四世代同時」都不算。本群組**不得豁免**，缺案例一律失敗。其他群組可在程式常數或 `--groups` 規則檔增加。
- **豁免：** 沒有資訊量的案例（例如 A、C 對稱抵銷、對加權目標價結構上恆為 0；或重算變動小於 0.001%）可不列，但 Sens 頁 A2 等註記（或任一列文字）須有一句（以「。」「；」或換行分句）同時含：該鍵、「不列」（或「豁免／免列／不另列」）、其後「：」接至少 4 個字的理由，且整句不含上述否定字。例：Meta「inc_m（價格情境差額的增量 EBITDA 率）不列：A、C 對稱且權重相同，對加權目標價結構上恆為 0」。只寫「beta 不列。」（無理由）、「beta 不得豁免」「beta 案例待補，不列入」都不算，列為「豁免不合格」。
- **只作對照、不進模型：** 低／高只作對照的列（市場共識目標價的最低／最高、舊版目標價等），在 In 頁該列說明欄（G 欄以後最後一個文字格）寫完整片語「只作對照，不進模型」即不列入待涵蓋。但核對程式會追引用鏈：引用該列 In 格（D／E／F）的公式（含加引號的工作表名、包住目標格的範圍、整欄／整列參照、指向它們的定義名稱與同名定義名稱）只可在 Recon、README、Sens（其下游也須全留在這三頁，例：SpaceX Recon!E14＝D14/C14−1），或 Val 頁「顯示用」格（本身沒有被任何公式或定義名稱引用）；INDIRECT、OFFSET 一律視為引用；其他引用即失敗（「寫不進模型但被 X 引用」）。進模型的輸入（例如價格證據 `p_spot`、`p_long`）不得這樣寫。`--all` 報告列「已排除鍵」。
- **警告：** In 頁 IF_HoldEcon 列有基準值但 D、F 都空白時輸出警告（該有區間卻沒填，本規則無法觸發；例：Microsoft v0.3.2 In 第 96–99 列 `tk_hold_*`）。
- **核對：** `tools/sens_coverage/check_sens_coverage.py <成品 xlsx> [--require-keycol]`（有未涵蓋即失敗）；`--all` 掃描全 repo 只報告（無 In 頁三欄的舊模板＝不適用）。測試 `tools/sens_coverage/test_check_sens_coverage.py`（含 10-30 獨立核對的反例）。報告中的「候選案例列」只以項目文字前綴比對，僅供人工參考，列號可能錯指，不影響判定。
- **現況：** 2026-10-30 首次掃描見 `docs/reports/20261030_敏感度覆蓋掃描.md`。Meta v0.1、SpaceX v0.1 通過；Alphabet v0.3.2、Oracle v0.4.1 缺 IF_HoldEcon 群組案例（失敗）；Microsoft v0.3.2 及多數 AI半導體 模型的 Sens 頁沒有「鍵」欄，須於下次改版補鍵欄、補案例或寫豁免。

## 10. 驗收衍生原則（Andy 2026-11-09 確認 SpaceX v0.2.5 驗收報告的採用規劃書；首例 SpaceX v0.2.6／v0.2.7）
採用規劃書：Drive `02-算力收支/個股模型/SpaceX/20261109_SpaceX驗收v0.2.5_採用規劃書.md`。驗收時**不需**驗收的項目見 `docs/plan/個股模型驗收_不需驗收項目.md`。新建或改版的個股模型一律套用以下各條；舊模型於下次改版時補上。
1. **建置快照要可辨識、可判斷是否過期：** `build_id`（版本＋建置輸入雜湊）在 README!A1、Sens 頁、HTML 三處相同；Sens 頁記錄敏感度重算時基準檔的 In 頁輸入指紋，與本檔即時指紋或基準目標價不同即顯示 STALE。核對：`tools/model_governance/check_governance.py`（建置腳本必跑）。
2. **每列單一主要標記：** In 頁、Q 頁只能是 Verified／Interested-party／Analogy／Assumed／Derived 之一；由原文相加、相除者標 Derived，不標 Verified；公司自揭 KPI、法說口頭與賣方標 Interested-party，並在「來源誘因」欄寫明誘因。同一列混有不同來源時，以最近一期原文的標記為主，其餘欄位寫在來源誘因欄。
3. **結論寫成條件式並列失效條件：** 投資建議句寫明承重假設（例：「在 k 依情境路徑收斂、自用 AI 採讀法 2 的基準假設下」）；README 與 HTML 列出主要失效條件（可觀察的證據）。
4. **主導變數要反解「支持現價所需的值」：** 以整本重算反解（例：SpaceX `kreq_v02.py`），寫在 Recon，不可借用指引校準值代替。反解值是「目標價＝現價」的點，不是評等門檻；失效條件要寫評等真正翻轉的條件（例：SpaceX 是 k 是否收斂，不是 2.9 倍）。
5. **期間並列：** Val 頁同時顯示模型折現期間（評價日起）與持有期間（現價日起），上檔空間不是年化報酬。
6. **未查核的數字不留在估值依據：** 說明欄的對照數字若未查核，刪除或寫「未查核，不作依據」。
7. **同業倍數同一估值日、同一 NTM 口徑：** 並列成長率、EBITDA 率、淨負債 ÷ EBITDA、資本強度（取不到時寫「未取得」並用代理）；每組少於約 8 家時不做迴歸。
8. **主導變數拆分項看可觀察程度：** 拆解表只引用 Tokenomics 快照與公司揭露；未揭露的分項寫「未揭露」，不在個股層重估 Tokenomics 權威參數（三層規則）。
9. **以新債補缺口時加融資可行性檢查：** 每年淨負債 ÷ 調整後 EBITDA（上限預設 4.5）與利息保障倍數（下限預設 3），超過只 WARN、不截斷；另列一個「融資受限：建置延後」Sens 案。完整內生融資模型不做。
10. **未建模的尾部風險列風險登錄：** 風險、是否建模、理由、觀察指標。
11. **評價日股數依 `docs/plan/個股DCF標準規格.md` 第 3 節（RSU 與選擇權庫藏股法進基準）。**
12. **自用 AI 讀法 2 仍為主值（第 7 節）：** 另在 Recon 並列影子效益對已可觀察 AI 產品利潤的倍數，讓讀者看見主值依賴假設的程度。
13. **文字中的數字一律公式組字**（2026-11-09 Arm v0.3.3 驗收衍生，Andy 確認；首例 Arm v0.3.4）：README、命題回覆、重點觀察、說明欄與 HTML 中的價格、倍數、百分比由儲存格組字，不手寫；舊版沿革列凍結為當時文字。
14. **歷史財務不內嵌在公式：** 歷史營收、折舊、資本支出、營運資金明細、股票薪酬、評價用資產負債、季 EPS 放 Hist 頁（或 In 頁獨立區塊；年度、單位、來源、標記），公式只引用儲存格（定義名稱 `h_*`）。
15. **單一資料基準日（as_of＝現價日）：** README 列各市場資料日期；與基準日相差超過 2 個交易日標「逾期」；最近一次財報前的共識標「財報前，只作歷史對照」。跨模型共用取值（rf、同業 EPS）逾期時，維持跨模型一致、於下次全面改版一併更新。
16. **證據鏈對稱：** README 說是主因的變數，Sens 必須有那一列（例：寫「DCF 低主因是股票薪酬」，就要有 `sbc_rev` 低／高）。
17. **公司揭露區間優先於類比：** Assumed／Analogy 參數若落在公司已揭露的區間之外，須有本專案自己的證據，否則移入區間；對公司不利的揭露（例：首代毛利低）可信度高於對公司有利的目標。
18. **缺資料的調整係數要明示：** 相對倍數等調整因缺資料而不調整時，寫「1.00（未調整：缺…）」並列入承重輸入；Comparable 依商業模式並列子群中位數（純展示）。
19. **事件型尾端風險進 Sens、不進基準：** 重大訴訟、單一地區或客戶占營收一成以上、關係人協議到期，各建一組尾端 Sens（基準 0）；其餘不可量化者進風險登錄（第 10 條）。
20. **承重 Assumed 驅動附可證偽指標：** README 為每個承重的 Assumed 驅動列一個公開可觀察的指標。

21. **已納入的事件，其價格同步進參數**（2026-11-09 Oracle v0.4.6 驗收衍生，Andy 確認；首例 Oracle v0.4.7）：模型納入新發債、增資、併購等事件時，相關成本參數（kd、新債利率、發行價、折價）改用該事件的實際定價（以公式引用事件列），舊值只作歷史對照。
22. **進現金流的 Assumed 參數都要有 Sens 列：** 不只 README 指為主因者；影響資金時點的參數（資本支出提前比例、付款條件、預付認列年數）也要有低／高。
23. **DCF 不省略營運資金：** 至少以「營運資金增加 ÷ 營收增量」的歷史比率（10-K 現金流量表營運資產負債變動，逐年與營運現金流勾稽）建簡化模組；預付、遞延收入等特殊項目另列，營收增量扣除非現金營收。
24. **評等分級只有一套邊界：** 模型的級距標籤、投資建議公式與目標價總表工具（`tools/target_summary/build_summary.py`：> +50%、> +25%、≥ −25%、≥ −50%）同一規則。
25. **方法名稱如實、揭露實際權重：** 混合方法不得只稱「Comparable」（抽取用的標籤前綴可保留，後面加註混合內容）；同一底層價值（例：AI 模組 DCF）同時出現在兩個方法時，Val 揭露它在加權目標價中的占比。
26. **目標價時點公式化：** In 頁設 `px_date`，`tp_date`＝`EDATE(px_date,12)`；README、Val 的日期由公式組字。
27. **會計年限與經濟壽命分開看：** 引用 Tokenomics 的折舊年限時寫明是會計口徑；Sens 除 TK 低／高欄外，加一個經濟汰換壓力案（標「待 Tokenomics 登錄」），證據經 `交流/` 送 Tokenomics。
28. **承重類比要核口徑、至少兩個：** 最承重的類比證據核對單位口徑（MW-IT 或設施）與服務範圍，並找第二個獨立類比；找不到寫「未找到」；第二類比落在評等翻轉值之外時，在報告中列為判斷題。
29. **模型參數與公司指標定義不同時寫明差異：** 公司指標只作 Interested-party 參照，不直接當參數。
30. **同業倍數註明會計口徑：** 同業列寫明 US GAAP／IFRS 與租賃處理，確認 EV 與 EBITDA 口徑和本公司一致；中位數落在口徑不同的同業時特別註明。
31. **敘事中的比較判斷由表格生成**（2026-11-09 Astera Labs v0.3.5 驗收衍生，Andy 23:22 確認採用規劃書；首例 Astera Labs v0.3.6）：「高於／低於／約等於／介於」等方向性敘述以公式依表格判定方向與幅度後組字；版本狀態字樣（實績／指引／假設）由 Q 頁狀態組字。結論依賴某倍數或權重時，句中寫出該條件，不寫無條件結論（第 13 條的延伸：不只數字，方向詞也不手寫）。
32. **目標價 Sens 涵蓋業務主因並顯示 DCF 單法：** README 指為主因的業務變數（份額、主要客戶轉單、GAAP 轉換等）在目標價 Sens 也要有列，不只在 EPS 表（無閉式時以整本重算快照，例 `alab/sens_alab.py`）；每列同時列 DCF 單法美元變化與加權目標價變化（第 16 條的延伸）。
33. **Recon 對照同口徑：** 與公司說法比較時分子分母定義須相同；口徑不同時改列隱含值（例：每顆營收 ÷ 公司採用平台每顆內容＝隱含採用率上限），不把差距百分比當成缺口（第 29 條的延伸，用於 Recon）。
34. **財報科目以法定申報為主來源：** Verified 的資產負債、現金流與股數科目以 SEC 10-Q／10-K（XBRL）或當地法定申報為主來源，資料商只作第二來源。
35. **比率參數以最近實績為起點**（J2 選項 b）：GAAP／non-GAAP 營業利益、股權報酬／營收等長期比率，基準用最近四季實績、全期持平，並列歷年實績；收斂路徑無證據時只作 Sens（低／高可用較早年度與最近一季）。
36. **評等貼近級距邊界時揭露距離**（J4 選項 a）：加權目標價上檔空間距最近級距邊界不到 5 個百分點時，README 與 HTML 橫幅寫明距離與「目標價達 x 即翻轉」；反解（第 4 條）以升一級、降一級的級距邊界為準（第 24 條的同一套邊界）。
37. **或有股份依合約閘門建模**（2026-11-10 AMD v0.4.4 驗收衍生，Andy 07:52 確認採用規劃書；首例 AMD v0.4.6）：客戶認股權證、業績型股份、earn-out 等，依合約已揭露的數量閘門（出貨、GW）、股價閘門、技術商業條件與**到期日**（到期未歸屬即失效）建模；歸屬量由模型推得的驅動量決定（驅動的 Sens 跟著變）；損益股數與 DCF 評價股數用同一套歸屬邏輯；未揭露的條件以 0％／50％／100％ 歸屬 Sens 呈現，不拆成未揭露的逐批參數（不需驗收清單 X19）。
38. **觸及夾值的係數要揭露並有 Sens：** 調整係數被上下限截斷時，README 與 Val 寫明原始值與夾值、列為承重輸入，Sens 加「不夾值」案例（第 18 條的延伸；夾值上下限本身為跨模型規則，不在單一個股改）。
39. **校準係數隨錨點重算：** 由 Assumed 錨點推得的校準係數（例：k_rec），錨點的 Sens 必須整本重算該係數與其後各年；以「總指引 − 其他分部」推得的錨點，Sens 要有其他分部合計誤差傳到錨點的案例。
40. **non-GAAP 起點的 DCF 附調節橋：** 逐項列 non-GAAP 調節（股票薪酬、併購攤銷、收購費用、法律或有損失、公允價值變動、營收減項、投資損益），標現金／非現金與 DCF 處理；折舊攤銷與 EBIT 同口徑；現金稅率（已付所得稅 ÷ non-GAAP 稅前）與模型稅率並列，差距大於 3 個百分點時加 Sens（不需驗收清單 X26：不改以 GAAP 三表重建）。
41. **三個日期分列：** README 首列與 HTML 表頭分列資料截止日、成品日、股價基準日，由公式組字（第 15、26 條的延伸）。
42. **停用方法不留在主敘述：** README、各頁標題與說明只描述現行方法；停用方法保留時標「舊法，不進結論」，沿用舊法計算的欄位改名「舊法…（參考）」。
43. **倍數一律標分母：** 每個「價格 ÷ EPS」寫明分母來源（模型哪個情境或哪個共識）、期間（FY／NTM）與日期；共識來源差距大時並列口徑與日期，未釐清前不據以下「市場錯估」結論。
44. **聯動的 Sens 要兩邊一起動：** 同源的價格與成本（例：售價隨 HBM 容量提高）在同一案例同步變動；只動一邊的案例須標「上界」；模型已讓成本隨營收等比例者，在 Sens 讀法寫明。
45. **承重外部輸入可由公開來源重建：** 記原始 URL、文件日期、頁碼或段落（例：8-K Item 1.01、新聞稿 Outlook 段）、擷取值與轉換式；repo 上游以檔名版本＋儲存格引用（X25）。
46. **情境涵蓋有機制的公司層共變驅動**（J2 選項 b）：有經濟機制與資料的公司層驅動（份額、大單時點、與加速器共變的 CPU 需求）在情境 A／C 自下一個會計年度起帶路徑（情境專屬列，不讀敏感度欄，第 8 節）；無機制或無證據者（稅率、其他業務）不分化，在情境驅動對照寫理由（X27）；情境 A／C 分化後 EPS 敏感度改以情境 B 為基準。
47. **上檔空間三段歸因與現行相對倍數**（2026-11-11 NVIDIA v0.3.4 驗收衍生，Andy 07:40 確認採用規劃書「請按預設繼續」；首例 NVIDIA v0.3.5）：README 與 HTML 橫幅以公式列出加權上檔空間＝DCF 貢獻＋未調整 Comparable 貢獻＋相對倍數調整貢獻；並列本公司現行前瞻倍數 ÷ 同業中位數與 10 年比值，寫明調整後 Comparable 需要的相對重估倍數；移除調整即翻轉評等時，橫幅寫明（第 18、31、36、38 條的延伸）。Sens 一律有「相對倍數係數＝1」目標價列。DCF 以 RONIC＝WACC、調整後 Comparable 以歷史溢價時，寫明兩法對競爭優勢的隱含假設相反。相對倍數調整本身仍在主估值（J1 選項 a；不需驗收清單 X30）。
48. **校準殘差的持續性要有 Sens**（J2 選項 a）：以基期錨點推得、沿用到預測期的校準係數（例：k_rec），Sens 至少有「持續」（基準）與「自下一會計年度起線性衰減、預測期第三年回到 1」兩案並整本重算；README 寫明基準選擇持續的理由（第 39 條的延伸；拆解未揭露分項依 X19 不做）。
49. **會計年度與上游日曆年以月數加權：** 公司會計年度與上游（日曆年）錯開 ≥ 1 個月時，以月數加權（例：1 月底年結 FY(t)＝11/12 × CY(t−1)＋1/12 × CY(t)；3 月底年結＝9/12 × CY(t−1)＋3/12 × CY(t)），不直接平移；季度出貨時點屬上游權威，不在個股估（X29）。
50. **基準與公司指引、命題設定的差距要標示並分解：** 基準落在公司已發布指引區間外時，README 與 HTML 標「高於／低於指引 x pt」，Recon 把差距分解到驅動，並反解達到指引所需的 Assumed 值（只展示、不校準，X3）；命題回覆依模型結果寫明支持或否定原設定；由 Assumed 輸入推得的結果寫明「模型輸出，非獨立證據」。
51. **展示層數字一致性檢查：** 建置時把 README 頁、HTML、repo `<公司>/README.md` 中的每個數字對回來源儲存格，不一致即失敗；repo README 版本表由建置輸出產生，不手寫（第 13 條的延伸）。
