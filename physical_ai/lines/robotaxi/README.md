# 線 1a Robotaxi｜單位經濟模型

AI實體應用專案的底層線模型。看的是美國 Robotaxi 在叫車市場的**滲透狀況**（城市、車隊、每週付費趟數、份額）和**每英里實收價格**，用來做傑文斯檢驗。v0.2 起加上**每英里成本堆疊**（本線權威：Waymo、Tesla Model Y、Tesla Cybercab、中國，2026–2032），比照 Tokenomics「每 GW 成本與營收」算「每英里成本與每英里價格」。框架見 `線1a_Robotaxi_框架_v0.1.md`。

## 頁面

說明｜輸入｜成本輸入｜CPUC資料｜計算｜接管轉成本｜每英里成本堆疊｜Tesla成本落差診斷｜每英里價格｜敏感度｜情境（2026–2035，分低、基準、高三情境）｜下游取數｜追蹤指標

- **成本輸入**：四個營運商 × 2026／2028（公式＝2026、2030 平均）／2030／2032 × 低成本／基準／高成本。低／高指成本，不是數值（壽命里程的低成本欄是較長壽命）；`PRICE` 列例外，低欄＝低價。
- **接管轉成本**：FSD 社群關鍵接管里程（版本別）當學習曲線 → Tesla 遠端協助率（K×1000÷MPI）、理賠率（1e6÷MPI×P_CLAIM）、遠端監看比（CONC0×G^(β×(年−2026))，上限 CONCMAX）。每營運商：遠端成本＝時薪×營運小時÷(每人監看車數×每車日付費英里)，每人監看車數取政策值與事件負載上限的較小者；安全員成本＝占比×時薪×營運小時÷每車日付費英里；保險＝MAX(理賠率×每件成本÷損失率, 保費下限)＋自身車損。
- **每英里成本堆疊**：十項（車輛攤提＝車價÷(壽命里程×付費占比)、融資、能源、維修清潔、保險與理賠、遠端營運、安全員／追車、場站與充電、軟體與研發攤提、平台抽成）；單位營運成本＝1–8，全成本＝1–10；與 1 美元、AAA 0.77 的差距；2026–2032 年度路徑（奇數年＝相鄰錨點幾何平均）與跨門檻年份。
- **Tesla成本落差診斷**：H1 安全員／追車、H2 稼動率（車隊小、服務區小）、H3 Model Y vs Cybercab、H4 遠端監看比、H5 保險與法規、H6 場站規模、H7 研發攤提、H8 其他。起點 Model Y 2026 基準、終點 Cybercab 2030 基準；每個假說算「單獨改善」「最後改善」與平均（近似 Shapley），再做依序瀑布（終點必須等於 Cybercab 2030 基準）。另有價格補貼檢驗與結論。
- **每英里價格**：觀察價格（含 Obi 單位更正的交叉驗證）、Tesla 票價依行程長度、各營運商價格路徑 vs 成本。

## 固定規格（專案規格 2026-11-16）

1. 重點放在滲透（城市、車隊、每週付費趟數、叫車市場份額），不放收支平衡。資料來源的優先順序：CPUC 季報 → TxDMV → 公司揭露 → YipitData／Second Measure → Obi／Gridwise → robotaxitracker.com 等社群追蹤。社群追蹤只當早期訊號用。
2. 核心指標是「每英里實收價格」，用來檢驗傑文斯效應：
   - 價格錨有兩個：人類叫車的每付費英里價格，以及自有車的每英里全成本（AAA 2025：平均 0.77 美元，小轎車 0.56 美元）。
   - 市場池分兩層：叫車池和自有車都會 VMT 池。價格跨過哪個錨，就打開哪個池。
   - 需求彈性分三個情境：−0.6／−1.0／−1.8（類比 NBER w31330）。
   - 下游要提供兩項：各情境的每英里價格路徑，以及傑文斯門檻價格。
3. 下游取數至少要有：美國叫車市場的總趟數與總里程、各情境的滲透率路徑、每英里營收區間、每英里成本區間。
4. 替代口徑（滲透模型）和含誘發口徑（傑文斯）不能相加，下游要擇一使用，並註明用哪一個。

## 固定規格（專案規格 2026-11-16，v0.2）

1. Robotaxi 比照 Tokenomics 的「每 GW 成本與每 GW 營收」，算「每英里成本與每英里價格」。每英里成本堆疊頁是本線權威，Waymo 與 Tesla Robotaxi 個股模型改讀這裡（`RT_CPM_*`、`RT_OPEX_*`）。
2. 預估 2030–2032 每英里成本能否降到約 1 美元（滲透自有車市場的門檻），並列與 AAA 自有車 0.77 美元的差距與跨越年份；全成本（含研發、平台）與單位營運成本（不含）兩個口徑都要列。
3. 診斷「Tesla 號稱成本可做很低、但目前看起來不是」的原因：逐項假說、證據、量化影響、何時可能消失、證偽指標。
4. 追蹤接管／遠端介入，並轉成成本，形成可連接的脈絡（接管里程 → 遠端協助率 → 監看比 → 遠端成本；接管 → 理賠率 → 保險）。
5. 稼動率（每車每日付費英里、空駛比）列為承重變數。
6. 追蹤每英里價格（依城市與行程長度）。
7. 公開 repo 不放工作情境：亞太標的一律寫「亞太掛牌」。

## 已知限制（v0.2）

- 車輛攤提依規格用「壽命里程」，未設日曆年上限；2026 Tesla 稼動很低時隱含壽命 9–16 年，車輛攤提偏低（但相對安全員、遠端成本是小項）。
- 遠端協助頻率與監看比沒有任何公司揭露（Markey 調查），全為 [Assumed]；Tesla 2026 監看比（CONC0）是單位成本最不確定的輸入。
- 研發攤提是分攤假設：Waymo 依 Other Bets 虧損推估量級；Tesla 只計 Robotaxi 營運軟體與地圖，FSD 核心訓練算力歸算力收支，不重複計入。全成本對車隊規模極度敏感。
- FSD 社群 tracker 為監督版、自願填報、非隨機樣本，與 CA DMV（有安全員測試、公司自定義）口徑不同，只作學習曲線斜率與量級對照。
- 中國以美元計（匯率 7.2），勞動與能源價格水準不同，不可直接與 AAA 0.77 比。

`check_robotaxi.py` 會檢查以下幾項：
- 0 個錯誤值
- 標記合法，Analogy 和 Assumed 都要有三個值
- 滲透率不超過覆蓋率，而且逐年不減
- 營運商份額加總為 1
- 每個年份的每英里毛利都是正數
- 三個情境的 2026 值一致，2030 年依低、基準、高的順序排列
- 下游 ID 不重複，必要的取數都在
- 五個敏感度目標都有排名（T3 改為 2030 Cybercab 全成本，新增 T5 2030 Waymo 全成本）
- v0.2：成本輸入標記與三值齊全；堆疊頁各項非負、全成本≥單位成本、每年低成本≤基準≤高成本、2030 低於 2026；Tesla 接管里程逐年上升；診斷頁起點與堆疊一致、瀑布終點等於 Cybercab 2030 基準；Obi 隱含每趟英里與 CPUC 都在 3–4.5 英里（單位更正）；不得出現工作情境字樣
