結論：類型加權消除了約四分之三的不一致，但**仍不一致，且無法以 Coding Plan 參數單獨消除**（所需使用率為負、快取命中 >1）；非 Coding Plan token（主要是 API 按量計費）換算 GW 也約為支出換算 GW 的 1.8 倍。剩餘殘差（η≈9.5）的可能來源，未自動調整：
1. **研發算力費含「雲端部署服務」**（SRC_ZP_230）：部分推論服務成本記在研發開支，推論算力支出（API 銷售成本）被低估。若研發算力費全數視為推論，1H26 η 約 2.8。
2. **Tokenomics 參考組合差異**：TK 單位成本以 DeepSeek V4-Pro 類（Sol，啟用 49B）為準；GLM-5.x 啟用約 40B，且 decode 批次、MTP、國產推論框架效率不同。
3. **Coding Plan 用量假設**：每次呼叫 20K token、每 prompt 17.5 次、使用率 0.15（INP_060–062）。
基準 η 沿用 1H26 → 2025、1H26 推論 GW 仍等於財報算力費換算值，殘差只影響 2H26 起「token 結構變化」的放大倍數。
