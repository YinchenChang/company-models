## 結論先行
1. **命題（每 VR 等值 GW 差額，含股權報酬）**：2025 −17,949 → 2026 −6,310 → 2027 −2,447 → **2028 轉正 +599** → 2029 +2,961 → 2030 +4,859（RMB 億／VR 等值 GW／年）；美元口徑 −266／−94／−36／+9／+44／+72（$B）。覆蓋率 0.16／0.52／0.77／1.07／1.37／1.70。以金額看，差額 −37.8／−37.6／−23.8／+8.1／+53.3／+114.7 億，2028 起營收超過全成本。**這個「轉正」高度依賴兩個假設**（見第 3、4 點），不應視為結論。
2. **為什麼每 VR 等值 GW 的數字這麼大**：智譜的算力是 Hopper、H20 與國產晶片，換成 VR200 等值只剩 0.056–0.068 倍；而且供給只有 0.03–0.42 GW（實體）。2030 以實體 GW 計，營收約 662 億／GW（$9.8B）、全成本約 389 億／GW（$5.8B），與 OpenAI v0.6（每 VR 等值 GW 營收 8.5、全成本 18.5 $B）同一量級；放大到 VR 等值是分母縮小的結果。
3. **η（有效產出係數）遠大於 1：2025＝49、1H26＝38（Checks WARN）**。意思是：用 Tokenomics 每 GW 產能換算，模型的 token 量需要的推論算力是智譜實際推論算力支出能買到的 38–49 倍。R4 對帳：**Coding Plan token 單項就是支出換算 GW 的 46 倍（2025）／36 倍（1H26）**；即使 Coding Plan 為 0，其餘 token 也超過 2 倍（使 η＝1 所需的額度使用率為負值）。所以不能只靠調 INP_060 解決（見「R4 結論」）。基準 η 沿用 1H26，2H26 起有效推論 GW 隨 token 成長。若 η 線性回升至 2030＝1（規格 D8 情境），2030 供給 16.1 GW、差額轉為 −5,200。
4. **供給 2H26 起依需求配置**（規格未定的機制；本段預設）：供給＝有效推論 GW ÷［(1−閒置)(1−研發占比)］，研發占比沿用 1H26 實際 0.70（較保守）。若研發占比線性降到 2030 的 0.5，2030 差額 +11,824（+6,965）。

## R4 結論：Coding Plan token 對帳
| 項目 | 2025 | 1H26 |
|---|---|---|
| 推論算力支出（API 銷售成本，D8r 上限） | 1.54 億 | 6.22 億 |
| 支出換算推論 GW | 0.00228 | 0.0218 |
| token 換算推論 GW（全部） | 0.112 | 0.834 |
| 其中 Coding Plan token 換算 GW | 0.104（93%） | 0.790（95%） |
| **Coding Plan token GW ÷ 支出換算 GW** | **45.8 倍** | **36.3 倍** |
| 使 token GW＝支出 GW 的 Coding Plan 額度使用率 | −0.0075 | −0.0043 |

- **不一致，且不能單靠 INP_060 解決**：使用率 0.05（區間下緣）時 η 仍為 18.1／14.0；要 η＝1，Coding Plan token 必須小於 0，代表連 API 按量計費與免費 token 換算的 GW（1H26 0.044）都已是支出換算 GW（0.022）的 2 倍。
- 可能原因（依可能性排序，未自動調整）：①Tokenomics 每 GW 產能是參考請求組合（DeepSeek V4-Pro 類、一般快取率），程式碼代理流量以長上下文快取命中為主，每 token 實際算力遠低於參考值；②SRC_ZP_230 註明研發算力費「含模型訓練及雲端部署服務」——部分推論服務成本記在研發，不在 API 銷售成本（D8r 低估推論支出）；若把研發算力費全算推論，1H26 η 仍約 11；③Coding Plan 每次呼叫 token（20K）、每 prompt 呼叫次數（17.5）偏高。
- 影響：η 吸收了這個不一致，所以 2025、1H26 的推論 GW 與算力成本仍等於財報；但 2H26 起 token 結構改變（按量計費占比上升）會放大誤差。INP_060 敏感度：0.05 → 2030 差額 −3,624（基準 4,859 → 1,235）、2030 供給 0.65 GW；0.4 → +2,423、供給 0.34 GW。方向與直覺相反：Coding Plan token 估得越少，η 越小，按量計費 token 每單位需要的算力越多。
- 建議（交 chat 端）：Tokenomics 增加「快取命中率／程式碼代理」負載的每 GW 產能（缺口）；Z4 前決定是否把 SRC_ZP_230 的「雲端部署服務」部分移入推論支出（需新 Inputs，規格未列）。
