# tools/coord — 三層協調 C4：對帳中標示與兩讀數目標價（共用工具）

規則：`docs/plan/三層基準協調規則.md` v1.4.2 C4（C0 對帳表見下節）（個股不裁決；估值依賴對帳中年份的硬體個股並列兩讀數目標價）。樣板 NVIDIA v0.3.8（`nvidia/coord_post.py`，專用）；Broadcom v0.5.5 起用本工具。

## 每家要做的事
1. **主引擎掛鉤（每家一處，依該模型的 Wattonomics 錨定參數名）：** `SIL.COORD_ALT`（環境變數 `SIL_COORD_ALT=1`）時，情境 B、C 於 CY2027 起產業量 × `wta_27`／`wta_28`／`wta_29`；情境 A 不縮放。該模式下 `siliconomics/reader.py` 的 `WTA` 改為另一側讀數比值（只在對帳中年份，其他年份＝1）。
2. `python3 tools/coord/alt_run.py <資料夾>` → `<資料夾>/coord_alt.json`（建置兩次、LibreOffice 重算、讀 Val 頁；檢查另一側建置的 wta 列確實＝比值、錯誤格 0）。
3. 建檔程式存檔前：`COORD.add_sheet(wb, <資料夾>, SIL)`（新增 Coord 頁；回傳非 None 時 `COORD.stamp(...)` 升版號）。
4. `gen_html_json.py` 最後：`COORD.inject_html(cfg, xlsx)`（橫幅一格＋揭露句、估值章開頭兩讀數表與長條圖）。
5. `siliconomics/builder/seed/coord_meta_v*.json` 的 `hardware_companies` 加入該資料夾，重匯 `baseline_status.json`；`tools/baseline_coordination/check.py` 第 6 項須通過。

## C0 由下往上對帳表（規則 v1.4.2 C0 第 2 點；Andy 11-14 17:40 固定規格）
每家 Coord 頁的 C0 對帳表：
- **個股側＝公司實績或法定揭露**（季報、年報、月營收、法說揭露的分部數字），寫明期間、口徑、出處（文件名與頁／表）。
- **層級側＝同口徑下由層級值推得的隱含值**（顆數 × 售價、份額 × 市場值等），連到層級值儲存格；口徑換算（會計年度、含不含網通、認列時差）另列並標等級。
- 差距超過 ±15% 標「對帳中」、開對帳單（Drive `02-AI供應鏈/對帳/`），不改上游。
- **不得用同源值：** 個股自層級讀入的值只列在「讀取層級」節，不進 C0 表（差距恆為 0，無檢驗力）。
- **兩層之間的差距**只列在「層級之間（參考）」節；**外部估計**（賣方、研調、指引）只列參考；兩者都不計入個股 C0。
- 沒有可比實績時寫「無可比實績」與缺哪一項揭露；遠年不做 C0。
- **層級值同源校準（11-14 核對教訓）：** 若層級隱含值的任一部分（份額、市場值、營收換算）是由本公司模型校準後寫入 Siliconomics（快照註記「公司模型校準值」或由本模型錨點反推），比式中層級市場值會消去，對帳實際只檢驗「實績 vs 本公司錨點」。此時判定標「參考（同源校準）」、不計入判定，C0 結論寫「無可比實績（層級值同源）」並說明缺哪一項獨立揭露；可見說明（Coord 說明列與 HTML 表下）寫明哪些量消去、這張表實際檢驗什麼。
- **實績期間：** 主讀數＝2026 年已公布期間累計 vs 層級 CY2026 × 月數 ÷ 12；第二讀數＝最近一季 × 4 vs 層級 CY2026（約等於該季中點的年化速率；最近一季落在年度後半時偏高、落在年中附近時大致無偏、加速成長時偏低——不得一律寫成「兩者夾住真值」）；兩者都超過 ±15% 且同號才「對帳中」，只一個超過為「時差邊界（參考）」。口述占比 × 營收屬 Assumed，不算公司實績。

## 追公式工具 trace_wattonomics.py（C0 之前必跑；MAG 類與其他算力買賣方共用）
C0 比較層級值前，先確認層級值有沒有讀本公司的實績或目標（同源）。工具把 Wattonomics xlsx 的某玩家輸出名稱沿公式追到輸入，Coord 頁追公式表貼它的輸出，不手寫。
```
python3 tools/coord/trace_wattonomics.py wattonomics/model/<Wattonomics>.xlsx <公司資料夾>/data/wattonomics_trace_<版>.json --player <碼> [--year 2026] [--roots "名稱:說明,..."] [--manual "鍵=標記"] [--md]
```
- `--player`：玩家碼（googl、msft、meta、orcl…）；旗標鍵 gcap_/cap_/act26_/w1_/obs_<碼> 由此組出。`--roots` 省略時追六個預設輸出（當年新增 GW、AI／非 AI 資本支出、前一年與當年底上線 GW、個股模型 AI 資本支出回寫）。
- 範圍參照（如 `Pipeline!$L$5:$L$150`）逐格展開並用正確工作表解析；Pipeline 頁只展開本玩家園區列（鍵含 `_<碼>_`），命中的園區列標「園區列」，其 In 頁輸入列標「園區輸入列（人工確認：多為公司公告）」（Microsoft Fairwater、Meta Prometheus 等）；JSON 的 `campus_rows` 列出命中的 Pipeline 列號。
- 每列輸出：`cell`、`parent`（上層格）、公式、值、`label`（In 頁鍵與名稱）、`flag`（同源旗標）、`status`：生效＝值沿此路徑傳到輸出；條件讀取＝只出現在 IF 條件、不傳值（例：Gap!G107 空白時 G104→G106→In!K172 營業現金流）；分支未生效＝IF 未取到的分支（目前只判頂層 IF；巢狀 IF 視為生效，須人工看）。
- 關鍵字誤觸者（如 `cap_g_ext` 外推年增、`ai_sh`）預設標「人工確認：不同源」，可用 `--manual 鍵=標記` 增補；`flag` 為「人工確認」者須人工判定，不自動當同源。與其他玩家無關的 In 頁列不追、不列。
- 反向查詢 `act26_readers`：哪些公式讀 `act26_<碼>`（公司已公布實績）；若只有 Compare 頁，代表實績未進 GW／資本支出路徑。
- 判定仍靠人：同源旗標只標「路徑上讀到公司輸入」，要看 `status` 是否生效、再把結論寫進 Coord 追公式列（整列同源→「參考（同源校準）」、「無可比實績（層級值同源）」；部分同源→改比每 GW）。
