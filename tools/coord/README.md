# tools/coord — 三層協調 C4：對帳中標示與兩讀數目標價（共用工具）

規則：`docs/plan/三層基準協調規則.md` v1.4.2 C4（C0 對帳表見下節）（個股不裁決；估值依賴對帳中年份的硬體個股並列兩讀數目標價）。樣板 NVIDIA v0.3.8（`nvidia/coord_post.py`，專用）；Broadcom v0.5.5 起用本工具。

## 每家要做的事
1. **主引擎掛鉤（每家一處，依該模型的 Wattonomics 錨定參數名）：** `SIL.COORD_ALT`（環境變數 `SIL_COORD_ALT=1`）時，情境 B、C 於 CY2027 起產業量 × `wta_27`／`wta_28`／`wta_29`；情境 A 不縮放。該模式下 `siliconomics/reader.py` 的 `WTA` 改為另一側讀數比值（只在對帳中年份，其他年份＝1）。
2. `python3 tools/coord/alt_run.py <資料夾>` → `<資料夾>/coord_alt.json`（建置兩次、LibreOffice 重算、讀 Val 頁；檢查另一側建置的 wta 列確實＝比值、錯誤格 0；檢查列與現行建置不同時警告，見下節）。
3. 建檔程式存檔前：`COORD.add_sheet(wb, <資料夾>, SIL)`（新增 Coord 頁；回傳非 None 時 `COORD.stamp(...)` 升版號）。
4. `gen_html_json.py` 最後：`COORD.inject_html(cfg, xlsx)`（橫幅一格＋揭露句、估值章開頭兩讀數表與長條圖）。
5. `siliconomics/builder/seed/coord_meta_v*.json` 的 `hardware_companies` 加入該資料夾，重匯 `baseline_status.json`；`tools/baseline_coordination/check.py` 第 6 項須通過。

## 兩讀數：另一側讀數的口徑（固定規格，2026-11-15）
- **另一側讀數不重算校準係數與指數分母；已實現與錨點期間不受縮放影響。** 理由：校準分母含 CY2026→CY2027 增量，縮放會使係數虛增、方向反轉。實作：校準與指數分母讀未縮放值（例：Disco v0.3.5 的 FY2025＝3/4 CY2025＋1/4 CY2026 新機需求，CY2026 新機需求讀未縮放的 CY2027 產能＝縮放後 ÷ `wta_27`）；另一側建置的實績與錨點檢查列須與現行建置相同（通常為 0）。
- 若兩讀數評等不同且取決於此口徑，Coord 頁與 HTML 揭露「若重算校準」時的另一側讀數目標價與評等（只列揭露、不進兩讀數表）。
- `alt_run.py` 讀兩次建置各頁「檢查」「核對」列（A 或 B 欄標題以此開頭，或含「應為 0」「應約 0」；以標題對應，不靠列號），另一側建置非 0 且與現行建置不同時印警告（不擋）。

## C0 由下往上對帳表（規則 v1.4.2 C0 第 2 點；Andy 11-14 17:40 固定規格）
每家 Coord 頁的 C0 對帳表：
- **個股側＝公司實績或法定揭露**（季報、年報、月營收、法說揭露的分部數字），寫明期間、口徑、出處（文件名與頁／表）。
- **層級側＝同口徑下由層級值推得的隱含值**（顆數 × 售價、份額 × 市場值等），連到層級值儲存格；口徑換算（會計年度、含不含網通、認列時差）另列並標等級。
- 差距超過 ±15% 標「對帳中」、開對帳單（Drive `02-AI供應鏈/對帳/`），不改上游。
- **不得用同源值：** 個股自層級讀入的值只列在「讀取層級」節，不進 C0 表（差距恆為 0，無檢驗力）。
- **兩層之間的差距**只列在「層級之間（參考）」節；**外部估計**（賣方、研調、指引）只列參考；兩者都不計入個股 C0。
- 沒有可比實績時寫「無可比實績」與缺哪一項揭露；遠年不做 C0。
- **層級值同源校準（11-14 核對教訓）：** 若層級隱含值的任一部分（份額、市場值、營收換算）是由本公司模型校準後寫入 Siliconomics（快照註記「公司模型校準值」或由本模型錨點反推），比式中層級市場值會消去，對帳實際只檢驗「實績 vs 本公司錨點」。此時判定標「參考（同源校準）」、不計入判定，C0 結論寫「無可比實績（層級值同源）」並說明缺哪一項獨立揭露；可見說明（Coord 說明列與 HTML 表下）寫明哪些量消去、這張表實際檢驗什麼。
- **實績期間：** 主讀數＝2026 年已公布期間累計 vs 層級 CY2026 × 月數 ÷ 12；第二讀數＝最近一季 × 4 vs 層級 CY2026（約等於該季中點的年化速率；最近一季落在年度後半時偏高、落在年中附近時大致無偏、加速成長時偏低——不得一律寫成「兩者夾住真值」）；兩者都超過 ±15% 且同號才「對帳中」，只一個超過為「時差邊界（參考）」。口述占比 × 營收屬 Assumed，不算公司實績。

## 追公式工具 trace_wattonomics.py（C0 之前必跑；MAG 類與其他算力買賣方共用）
C0 比較層級值前，先確認層級值有沒有讀本公司的實績或目標（同源）。工具把 Wattonomics xlsx 的某玩家輸出名稱沿公式追到輸入，Coord 頁追公式表貼它的輸出，不手寫。
```
python3 tools/coord/trace_wattonomics.py wattonomics/model/<Wattonomics>.xlsx <公司資料夾>/data/wattonomics_trace_<版>.json --player <碼> [--year 2026] [--roots "名稱:說明,..."] [--manual "鍵=標記"] [--md]
```
- `--player`：玩家碼（googl、msft、meta、orcl…）；旗標鍵 gcap_/cap_/act26_/w1_/obs_<碼> 由此組出。`--roots` 省略時追六個預設輸出（當年新增 GW、AI／非 AI 資本支出、前一年與當年底上線 GW、個股模型 AI 資本支出回寫）。
- **生效判斷**：IF 的條件用快取值遞迴計算（`ref<>""`、`ref=""`、常數比較如 `2026>=2026`、`INT(名稱)=年`、AND／OR／NOT／N／ISNUMBER 等），巢狀 IF 逐層處理；條件為真只取第一支、為假只取第二支，沒取到的分支標「分支未生效」，條件本身標「條件讀取」。算不出來（不支援的函數、範圍）時兩支都當生效並在輸出 `unparsed` 或須人工確認。驗證例：msft 的 CapexGW!G35＝`IF(2026>=2026,F35+G34,N(Players!G30))` 中 Players!G30 為分支未生效；msft 2025 年底 GW（Players!F23＝chip_msft × 倍數，不同源）生效，obs_msft 與 Pipeline 園區列為分支未生效。
- **SUMIFS／COUNTIFS／SUMIF** 依條件欄逐列判斷：文字相等條件（營運者欄＝玩家碼、鍵欄＝園區鍵）不符的列整列不追（用公式裡的條件欄，不靠鍵名猜）；年度、納入等數值或比較條件不符的列標「條件讀取」。已對 googl、msft、meta、oai、neo、sov 驗證：命中的 Pipeline 列與營運者欄＝該玩家的列完全一致。
- **Pipeline／FundRaw**：兩頁的格子都標旗標（Pipeline＝園區列，其 In 輸入列標「園區輸入列（人工確認：多為公司公告）」，如 Microsoft Fairwater、Meta Prometheus；FundRaw＝公司實績〔10-K／10-Q〕）。其他範圍參照在這兩頁只展開列內有玩家碼的列。JSON 的 `campus_rows` 列出命中的 Pipeline 列號。
- 每列輸出：`cell`、`parent`（上層格）、公式、值、`label`（In 頁鍵與名稱）、`flag`、`status`（生效＝值沿此路徑傳到輸出；條件讀取＝只在 IF 條件或 SUMIFS 條件欄；分支未生效＝IF 沒取到的分支；例：Gap!G107 空白時 G104→G106→In!K172 營業現金流為條件讀取）。
- 旗標鍵由 `--player` 組出（gcap_／cap_／act26_／w1_／obs_ 加玩家碼）。鍵含本玩家碼的跨玩家列（ctr_msft_ant、xc_nbis_msft、al_orcl_oai）保留；只含其他玩家碼的 In 列不追。關鍵字誤觸者（`cap_g_ext`、`ai_sh`）預設標「人工確認：不同源」，可用 `--manual 鍵=標記` 增補；`flag` 為「人工確認」者須人工判定。g_ITtoFac 等不含玩家碼的共用係數不標園區輸入。
- 反向查詢 `act26_readers`：哪些公式讀 `act26_<碼>`；只有 Compare 頁，代表實績未進 GW／資本支出路徑。
- **SUMIFS 條件比對與 Excel 一致**：數值條件（含字串 '2026'）同時比對數字與看起來是數字的文字；文字條件不分大小寫比對文字或數字。FundRaw 的期間欄、採用欄是文字（'2026'、'1'），因此能正確命中。若公式的結果直接就是 SUMIFS／SUMIF、條件全不符、快取值卻非 0 非空，該公式列入 `unparsed`（防止列被靜默丟棄）。驗證例：`--player msft --roots "Funding!E7:x"` 追到 FundRaw 第 16 列（G16＝182.935），標「公司實績（10-K／10-Q，FundRaw）」。
- **與快取值對照（unparsed）**：COUNTIFS／SUMIFS／SUMIF 也用快取值重算（條件比對同上），讓 `IF(COUNTIFS(...)=0,"",SUMIFS(...))` 這類條件能判定。IF 選出的分支若是常數或單一參照，與該格快取值比對；不一致就把該格列入 `unparsed`、兩支都當生效，並註明 IF 分支內 SUMIFS 是否零命中。SUMIFS 為結果節點時，重算值與快取值不一致也列入。反向測試：把 FundRaw!E16 的 '2026' 改成 '2099'、保留快取值，Funding!E7 會被列入 `unparsed`。
- **最上層 status 與逐根狀態**：每列最上層 `status` 取各根中最高者（生效 > 條件讀取 > 分支未生效）；某根下是否生效必須逐根看 `roots`，不能只看最上層。摘要的「旗標輸入」含 FundRaw 公司實績（不含 Pipeline 園區列本身）。
- **多根記錄**：每格的 `roots` 記錄經過該格的每個根及其在該根下的狀態；JSON 另有 `root_flags`（各根下被旗標的輸入格與狀態），避免誤讀「某根看不到公司輸入」。`--roots` 可直接給 `Sheet!Cell`。
- 限制：不支援整欄參照（`A:A`）與未列的函數；上線 GW 根的生效判斷若有 `unparsed`，須人工確認。無 Gap 名稱的玩家（neo、sov 等）用 `--roots` 指定根。
- 判定仍靠人：同源旗標只標「路徑上讀到公司輸入」，要看 `status` 是否生效、再把結論寫進 Coord 追公式列（整列同源→「參考（同源校準）」、「無可比實績（層級值同源）」；部分同源→改比每 GW）。

## 外部稽核優化 W3-1、W3-3（2026-11-23）
- **Comparable 列標籤**：兩讀數表的 Comparable 列是未調整的市場主流同業法，不進加權（進加權的是相對倍數調整後，規則 X30）。`add_sheet` 在模型有 `tp_comp_adj` 時把列名寫成「…未調整，不進加權」，並在同一列 E–G 欄並列「相對倍數調整後；進加權」的兩讀數值（另一側＝另一側未調整值 × 現行調整後 ÷ 現行未調整）。放右側而不插列，既有儲存格位置不變。`inject_html` 在兩讀數表多列這一列。
- **評等不同的提示**：兩讀數評等不同時，`tools/company_html/build_company_html.py` 的橫幅另起一行提示（讀 Coord 頁「投資建議」列 B、C 欄，各家不必改 html.json）；算力地圖的註記欄同樣加一句（`markets/invest_map/extract_models.py` 的 `coord` 欄）。並列是規則 C4 的要求，不是缺陷。
