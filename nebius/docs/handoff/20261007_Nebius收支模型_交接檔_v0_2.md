# Nebius 收支模型 — 交接檔（v0.2，2026-10-08；資料更新日 2026-10-07）

## 1. 這是什麼（命題）
Nebius（NBIS）的資金與評價模型。命題：Nebius 用**客戶預付款**而非資產層債務支應大部分擴張資本支出——檢驗在 Tokenomics 正向推導的每 MW 經濟性下，擴張到 5 GW 合約電力能否不依賴持續的股權與可轉債稀釋，也就是 CRWV「Backlog 不是現金」的對照組：**預付款是否讓 backlog 真的變成現金**。

**標題**：「預付款，能把 Backlog 變成現金嗎？」（v0.2；`company.json` → `texts.title`）。副標題一句話答案由模型現值帶入：客戶預付只覆蓋約 36% 的資本支出；剩下 $59.8bn 缺口仍靠資產擔保債、可轉債與新股——現價要成立，每 MW 年收入得是模型的 1.7 倍（基準情境；隨情境切換）。

**目前答案（v0.2 第 2 輪；基準與 v0.1 相同，保守、積極見下）**：預付款是真的現金（上半年約 4.55bn），能大幅減少稀釋（基準情境少發約 1 億股、目標價高約 $17），但不足以讓現價成立：三情境目標價 保守 $35.2／基準 $61.7／積極 $154.6，全部「賣出」（現價 $249.87，賣出門檻 $212.4）。信心中等：最大的不確定是每 MW 年收入（正向推導 11.6–24.2 vs 目前實現約 6.4 vs 公司 ACV 20–25）。

模型同時輸出 HTML（互動、可調輸入）與 Excel（全部活公式），兩者數字必須一致（cmp31 三情境＋FY27 錨定各 335 項）。

## 3. 模型結構與因果
**因果主軸**：已連網 MW → 可計費 MW → 營收 → EBITDA → 營運現金（＋客戶預付）− CapEx → 融資缺口 → 瀑布（資產擔保融資 → 可轉債 → ATM 股權 → 高息債）→ 股數與淨負債 → DCF＋EV/EBITDA → 目標價。

| 區塊 | 公式與輸入（`company.json` 位置） |
|---|---|
| 已連網 MW-IT | 期末＝MIN(合約上限, 前期＋併網速度 × 期間長度)；首期期末 750（`scenarios.mwPath`） |
| 可計費 MW（v0.1c 首期營收校準） | 期初＝最新季營收 × 4 ÷ 首期每 MW 年收入（保守 200／基準 134／積極 96；`latestQuarter.revenue`、`defaults.billableOpen`＝預設情境值，建置時檢查）；期末＝已連網 × 在役比例 0.75／0.85／0.90… × 爬坡係數 60%／80%／100%…（`scenarios.billableRatio.ratio`、`.ramp`） |
| 營收 | 平均可計費 MW × 每 MW 年收入（保守 11.62／基準 17.40／積極 24.20 US$m／MW-IT·年，`scenarios.revMW`，Tokenomics 正向推導）× 期間長度；RPO（37.5bn）只作對照與資產擔保融資上限的 backlog |
| EBITDA | 營收 × EBITDA 率（49.7% 線性走向穩態 47%，`defaults.ebStart`／`ebSteady`）＋其他事業 EBITDA（−0.188／年遞減至 FY30 為 0，`defaults.otherEbitda`） |
| CapEx | 依新增已連網 MW × 每 MW 建置成本（Tokenomics IF_CapexTotal 50.1–50.3 US$m／MW-IT，`scenarios.capexTemplate.costMW`），λ＝35% 預建；GPU 壽命 5 年汰換 |
| 預付款（新） | 預付流入＝成長型 CapEx × 70% × 55%（`defaults.prepay`）；期初合約負債 5.975（6/30 遞延營收）依 3 年直線認列為非現金營收，自營運來源與 UFCF 扣除 |
| 融資瀑布 | 預付 → 現金（高於最低現金 2）→ 資產擔保融資（未動用 0.775＋新債，總債務 ≤ 0.5 × backlog，6.5%）→ 可轉債（每年上限 0／5／10bn，票息 2.1%，`scenarios.convCap`、`defaults.convIssue`）→ ATM 股權（現價 × 0.9，每年 ≤ 現市值 20%）→ 高息債 12% |
| 可轉債稀釋（新） | 八檔（`debt.convertibles`）；有效轉換價（轉換價 × 到期累積倍數）< 判斷價 → 若轉換法（加股數、不計利息與還本），否則為債務；融資判斷價＝現價、評價兩輪（第二輪＝MIN(現價, 第一輪目標價)） |
| 其他事業與持股（新） | 淨負債調整項＝−(ClickHouse 15 × 25% ＋ Toloka 0.0865) × (1 − 30%) ＋ Avride SAFE 0.178＝−2.507（`valuation.holdings`、`debtLike`） |
| 評價 | DCF 45%（0 截斷）＋ EV/EBITDA 6x（錨定 FY29，折回目標價時點）55%；DCF 失效只限 WACC ≤ g（權重歸零）；常態化 FCF ≤ 0 時終值以 0 計、DCF 照常 0 截斷並保留 45% 權重（v0.2 第 2 輪）；目標價時點＝評價日（2026-06-30）＋12 個月；淨負債不含可轉債（−13.675，含期後淨現金 5.68），股數 0.3193bn |
| 季度層、期間滾動、共識 | 沿用 CRWV v4.5（日曆財年 12 月；評價日＝最新已申報季末） |

## 8. 已知限制
1. **未做續約價格衰退**（CRWV 尚未做；對照表 r1 預設 3）：每 MW 年收入五期固定，GPU 世代老化與續約降價未反映——預付款優勢與後段營收可能**高估**，目標價偏高。
2. **實現單價遠低於推導單價**：Q2 實現約 6.4M／在役 MW 對推導 11.6／17.4／24.2；模型把差距歸為爬坡（C4），若實為長期單價偏低，目標價再降（基準改用 11.62 為 $51.5）。
3. 車隊折舊以期初毛 PP&E（含尚未啟用資產）計，高於實際走勢（CRWV 待辦 6，未做）。
4. WACC 11% 與 EV/EBITDA 6x 沿用 CRWV 模板，未另估 Nebius（淨現金、槓桿較低）；偏保守。
5. 保守情境常態化 FCF ≤ 0，DCF 腿為 0 並保留 45% 權重（v0.2 第 2 輪前判為失效、EV/EBITDA 100%，造成「利潤率愈低目標價愈高」的跳躍）；積極情境 EV/EBITDA 腿單獨 $249.8 約等於現價——賣出結論依賴 DCF 腿與 6x 為上緣。
6. 保守情境股權每年觸及上限（現市值 20%），溢出以高息債補足。
7. 機率加權目標價、GPU 批次、5a 精簡、5b 只讀檢視器未做（範圍外）。
8. LibreOffice 計算模擬運算表會留殘值，`xlx.py` 以兩輪重算處理；Excel 本身不受影響。
9. 同業 Comps 市值與淨負債為 2026-09-21，未更新。

## 10. 如何重建
1. 環境：LibreOffice Calc（`soffice --version`；缺時 `apt-get install -y --no-install-recommends libreoffice-calc-nogui`）、Python `openpyxl`、`playwright`（1.56.0）＋ Chromium、Node.js。
2. 在 `nebius/` 執行 `scripts/verify.sh`：季度層檢查 → README 欄位說明檢查 → 建 HTML → 建 Excel → LibreOffice 重算（公式錯誤須 0）→ 反向 DCF 以 Excel 求解（`rv_snap.json`）→ fix_outline → fix_datatable → verify_ooxml → 離線開啟檢查 → 三情境與 FY27 錨定 cmp31 → 季度層、期間滾動、拆解工具測試；18 項全過。產物在 `out/`（不入版控）。
3. 成品：`DATE=2026-10-07 scripts/verify.sh` 產生 `out/20261007_Nebius收支模型_v0_2.html`／`.xlsx`，複製到 `dist/`；再跑 `scripts/verify.sh --vs-dist`（21 項，畫面文字與 Excel 值、公式 0 差異）。升版時對舊成品比對：`EXPECT=scripts/expect/<新>_vs_<舊>.txt CRAWL_EXPECT=scripts/expect/<新>_vs_<舊>_crawl.txt scripts/verify.sh --vs-dist`（v0.2 對 v0.1 的清單在 `scripts/expect/v0_2_vs_v0_1*.txt`）。簡報改動後以 `python3 scripts/shot_deck.py <html> <資料夾>` 逐頁截圖自查。
4. 改輸入：只改 `company.json`（新欄位要在 `scripts/fields_doc.py` 補說明並 `--write`）；改公式：Excel 在 `build_xlsx.py`、HTML 在 `segA.js`～`segE.js`，兩邊須經 cmp31 一致；`CLAUDE.md`「勿改」各條仍適用。
