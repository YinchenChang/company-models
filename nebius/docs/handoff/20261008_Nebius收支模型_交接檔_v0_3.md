# Nebius 收支模型 — 交接檔（v0.3，2026-10-08；資料更新日 2026-10-08）

## 1. 這是什麼（命題）
Nebius（NBIS）的資金與評價模型。命題：Nebius 用**客戶預付款**而非資產層債務支應大部分擴張資本支出——檢驗在 Tokenomics 錨定的每 MW 經濟性下，擴張到 5 GW 合約電力能否不依賴持續的股權與可轉債稀釋，也就是 CRWV「Backlog 不是現金」的對照組：**預付款是否讓 backlog 真的變成現金**。

**標題**：「預付款，能把 Backlog 變成現金嗎？」（`company.json` → `texts.title`）。副標題一句話答案由模型現值帶入（v0.3）：客戶預付只覆蓋約 36% 的資本支出；剩下 $55.8bn 缺口仍靠資產擔保債、可轉債與新股——模型每 MW 年收入已是 Tokenomics 打平租金的 1.6 倍，現價要成立得到 2.4 倍（基準情境；隨情境切換）。

**目前答案（v0.3；每 MW 收入改以 Tokenomics 為錨）**：預付款是真的現金（上半年約 4.55bn），能大幅減少稀釋，但不足以讓現價成立：三情境目標價 保守 $81.8／基準 $72.5／積極 $87.8，全部「賣出」（現價 $249.87，賣出門檻 $212.4）。每 MW 年收入（基準）＝Tokenomics 錨 11.6–12.5 × 定價倍數 k 1.22–1.58＝14.2（FY26）→ 19.9（FY30）US$m／MW-IT·年；最大的不確定改由「價格軸」表達：同一容量下 k 低／基準／高，基準目標價 $55.3／$72.5／$161.7（容量 × 價格 3 × 3 九格全部低於賣出門檻 $212.4，最高為積極 × 價格高 $202.9）。信心中等。

模型同時輸出 HTML（互動、可調輸入）與 Excel（全部活公式），兩者數字必須一致（cmp31 三情境各 370 項＋FY27 錨定 358 項）。

## 3. 模型結構與因果
**因果主軸**：已連網 MW → 可計費 MW → 營收 → EBITDA → 營運現金（＋客戶預付）− CapEx → 融資缺口 → 瀑布（資產擔保融資 → 可轉債 → ATM 股權 → 高息債）→ 股數與淨負債 → DCF＋EV/EBITDA → 目標價。

| 區塊 | 公式與輸入（`company.json` 位置） |
|---|---|
| 已連網 MW-IT | 期末＝MIN(合約上限, 前期＋併網速度 × 期間長度)；首期期末 750（`scenarios.mwPath`） |
| 可計費 MW（v0.1c 首期營收校準；v0.3 首期每 MW 年收入三情境同為 14.16 → 期初 165） | 期初＝最新季營收 × 4 ÷ 首期每 MW 年收入（v0.2：保守 200／基準 134／積極 96；`latestQuarter.revenue`、`defaults.billableOpen`＝預設情境值，建置時檢查）；期末＝已連網 × 在役比例 0.75／0.85／0.90… × 爬坡係數 60%／80%／100%…（`scenarios.billableRatio.ratio`、`.ramp`） |
| 營收（v0.3） | 平均可計費 MW × 每 MW 年收入（100% 計費時數）× 利用率 100% × 期間；每 MW 年收入＝Σ 平均在役世代占比（`fleet`）× Tokenomics `IF_HoldEcon`（基準成本情境，`TK_HoldEcon_<世代>`）× 定價倍數 k；k＝長約占比 × k_長約 0.76＋（1 − 長約占比）× k_現貨 1.76（`pricing.anchorMultiple`）；長約占比＝MIN(1, Microsoft 205＋Meta 46〔＋Meta 第二份 188 自 FY27〕MW ÷ 平均在役 MW)。基準：14.16／15.05／17.97／19.21／19.87 US$m；容量情境只改 MW，價格情境（低／基準／高）只改 k。**按 MW-year 計價**：收入取決於簽約率與爬坡，不乘 Tokenomics `IF_Util`（下游資料契約第 3 條）。舊三情境 11.62／17.40／24.20（`scenarios.revMW`）為 legacy 與對照列 |
| EBITDA | 營收 × EBITDA 率（49.7% 線性走向穩態 47%，`defaults.ebStart`／`ebSteady`）＋其他事業 EBITDA（−0.188／年遞減至 FY30 為 0，`defaults.otherEbitda`） |
| CapEx | 依新增已連網 MW × 每 MW 建置成本（Tokenomics IF_CapexTotal 50.1–50.3 US$m／MW-IT，`scenarios.capexTemplate.costMW`），λ＝35% 預建；GPU 壽命 5 年汰換 |
| 預付款（新） | 預付流入＝成長型 CapEx × 70% × 55%（`defaults.prepay`）；期初合約負債 5.975（6/30 遞延營收）依 3 年直線認列為非現金營收，自營運來源與 UFCF 扣除 |
| 融資瀑布 | 預付 → 現金（高於最低現金 2）→ 資產擔保融資（未動用 0.775＋新債，總債務 ≤ 0.5 × backlog，6.5%）→ 可轉債（每年上限 0／5／10bn，票息 2.1%，`scenarios.convCap`、`defaults.convIssue`）→ ATM 股權（現價 × 0.9，每年 ≤ 現市值 20%）→ 高息債 12% |
| 可轉債稀釋（新） | 八檔（`debt.convertibles`）；有效轉換價（轉換價 × 到期累積倍數）< 判斷價 → 若轉換法（加股數、不計利息與還本），否則為債務；融資判斷價＝現價、評價兩輪（第二輪＝MIN(現價, 第一輪目標價)） |
| 其他事業與持股（新） | 淨負債調整項＝−(ClickHouse 15 × 25% ＋ Toloka 0.0865) × (1 − 30%) ＋ Avride SAFE 0.178＝−2.507（`valuation.holdings`、`debtLike`） |
| 評價 | DCF 45%（0 截斷）＋ EV/EBITDA 6x（錨定 FY29，折回目標價時點）55%；DCF 失效只限 WACC ≤ g（權重歸零）；常態化 FCF ≤ 0 時終值以 0 計、DCF 照常 0 截斷並保留 45% 權重（v0.2 第 2 輪）；目標價時點＝評價日（2026-06-30）＋12 個月；淨負債不含可轉債（−13.675，含期後淨現金 5.68），股數 0.3193bn |
| 季度層、期間滾動、共識 | 沿用 CRWV v4.5（日曆財年 12 月；評價日＝最新已申報季末） |

## 8. 已知限制
1. **未做續約價格衰退**（CRWV 尚未做；對照表 r1 預設 3）：每 MW 年收入五期固定，GPU 世代老化與續約降價未反映——預付款優勢與後段營收可能**高估**，目標價偏高。
2. **實現單價遠低於錨 × k**：Q2 實現約 6.4M／在役 MW 對模型 FY26 14.2；Q2 驗證拆解 99% 歸為爬坡分母（計費 165 對在役 366 MW），若實為長期單價偏低（Q2 隱含 k 0.56），目標價再降（價格低情境基準 $55.3）。
2b. **收入上限檢查警示**：每 MW 年收入占 Tokenomics 客戶每 MW token 營收 50–69%（門檻 50%）；Tokenomics 的客戶營收是 OpenAI 有效單價的理想上限。
2c. **終值與 DCF 腿**：基準與積極 DCF 腿為 0（0 截斷），目標價全由 EV/EBITDA 腿（FY29 × 6x）決定；保守 DCF 腿 $13.9。
2d. **世代汰換未做**：Hopper 在 FY29–FY30 才屆 5 年，影響錨約 0.1 以內。
3. 車隊折舊以期初毛 PP&E（含尚未啟用資產）計，高於實際走勢（CRWV 待辦 6，未做）。
4. WACC 11% 與 EV/EBITDA 6x 沿用 CRWV 模板，未另估 Nebius（淨現金、槓桿較低）；偏保守。
5. 保守情境常態化 FCF ≤ 0，DCF 腿為 0 並保留 45% 權重（v0.2 第 2 輪前判為失效、EV/EBITDA 100%，造成「利潤率愈低目標價愈高」的跳躍）；積極情境 EV/EBITDA 腿單獨 $249.8 約等於現價——賣出結論依賴 DCF 腿與 6x 為上緣。
6. 保守情境股權每年觸及上限（現市值 20%），溢出以高息債補足。
7. 機率加權目標價、GPU 批次、5a 精簡、5b 只讀檢視器未做（範圍外）。
8. LibreOffice 計算模擬運算表會留殘值，`xlx.py` 以兩輪重算處理；Excel 本身不受影響。
9. 同業 Comps 市值與淨負債為 2026-09-21，未更新。

## 10. 如何重建
1. 環境：LibreOffice Calc（`soffice --version`；缺時 `apt-get install -y --no-install-recommends libreoffice-calc-nogui`）、Python `openpyxl`、`playwright`（1.56.0）＋ Chromium、Node.js。
