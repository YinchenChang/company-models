# Nebius v0.1 分段建置：共同規則（2026-10-07，chat 端）

適用於工作單 v0.1a、v0.1b、v0.1c。每張工作單開工前必讀本檔、該張工作單、`nebius/docs/plan/20261007_Nebius_命題與驅動對照表_r1.md`、repo 根目錄 `README.md`、`nebius/CLAUDE.md`、`nebius/README.md`。
三者衝突時的優先順序：**該張工作單 > 本檔 > repo 根目錄 README > nebius/CLAUDE.md**（CLAUDE.md 是 CRWV 時期的守則，其中「判斷口徑停下來問 Andy」「共識數據只能由 Andy 提供」兩條，本次由工作單取代，見下）。

## 1. 為什麼分段
上一輪一次做到底，額度用完時建置進度全部遺失（遠端只剩一份進度檔）。本次規則：**每完成一個步驟就 commit 並 push，同時覆寫進度檔**。任何時候中斷，下一個代理都能從進度檔接手，不需重做。

## 2. 分支、PR、合併
- 每張工作單一個分支、一個 PR（base `main`）。分支名寫在各工作單。開工第一步：從最新 `main` 開分支、push、開 draft PR。
- 開 PR 用 GitHub REST API（`gh api repos/YinchenChang/company-models/pulls -f ...`）；GraphQL 在此環境不可用。
- **代理不得合併、不得 force push、不得改 `main`、不得刪除分支或歷史。** 合併由 chat 端審查後執行。
- 推送前先 `git fetch origin main`；淺層 clone 推送若遇 HTTP 413，先 fetch 再推。

## 3. 進度檔（接手用，必做）
- 路徑：`nebius/docs/reports/20261007_nebius_進度.md`（三張工作單共用一份；每張開工時在檔內新增自己的段落，不刪其他段落）。
- 檔案最上方「目前狀態」每次 push 前覆寫，固定三項：**已完成**（含 commit 編號）／**下一步**（具體到下一個代理可以直接動手）／**未解問題**。
- 下方「步驟紀錄」表：步驟｜狀態｜commit｜備註。
- 每個步驟完成 → 更新進度檔 → commit → push，三件事一起做，不得累積多步才 push。
- 若察覺額度或時間快用完：立即停止新工作，先把手上成果 commit、更新進度檔（寫清楚做到哪一行、下一步），push 後再結束。

## 4. 資料紀律
- 每一筆數字都要有：數值、單位、期間、來源（文件名稱＋網址）、文件日期、擷取日、標記。
- 標記：[Verified] 可公開查證；[Interested-party] 來源有利害關係（寫明是誰與動機，例如公司自述、賣方分析師）；[Analogy] 由可比對象推估（寫明對象與差異）；[Assumed] 無實證；[Derived] 由其他數字換算（寫明公式）。Analogy／Assumed 一律給區間，不給單點。
- 公司自己的財報數字（6-K、20-F、新聞稿、股東信）＝[Interested-party]（公司自述），但經查核師簽證的 20-F 財務報表可標 [Verified]。
- **不得杜撰數字。** 找不到就標「不適用」或列入資料缺口，寫明試過哪些來源。「找不到」與「不存在」要分開寫。
- **SemiAnalysis（含 InferenceX）類資料不可單獨引用**：必須有第二個獨立來源佐證；沒有就只列為參考、不作輸入。
- **不以公司自己的數字反推參數**（例如以公司 ACV ÷ MW 回推單價、以營收指引回推利用率）。每 MW 單價先由 Tokenomics 正向推導，公司數字只作對照列。
- 同一來源的多個呈現（例如 StockAnalysis 與 MarketScreener 都引用 S&P Capital IQ）不算獨立交叉驗證，要寫明。

## 5. 判斷類事項
- 照對照表 r1 第 4 節的預設處理，不停下來問；對照表沒涵蓋的判斷，選最保守且最常見的口徑作預設，並在進度檔與最終報告「已套用的預設」逐項列出：問題｜採用的預設｜替代選項｜對結果的影響方向（能量化就量化）。
- 範圍：做到 CRWV v4.5 水準；CRWV 未完成的待辦（5a 精簡、5b 只讀檢視器、折舊修正、機率加權目標價、GPU 批次與續約價格衰退）不做。

## 6. 停止條件（只有碰到這些才停下找 Andy；其餘一律照預設做完）
1. 必要的 repo（`YinchenChang/company-models`、`YinchenChang/Tokenomics`）無法讀取或無法推送。
2. 主要一手來源全部無法取得（SEC EDGAR 與 Nebius 投資人關係網站都拿不到最新季度財報），以致核心欄位只能靠二手來源。
3. 同一個 verify 失敗，經三次實質不同的修正仍無法通過，且原因是模板結構限制而非本次改寫的錯誤。
4. 要讓模型成立，必須做第 5 節列為「不做」的範圍。
5. 需要改 `main`、force push、刪除分支或歷史。

停下時：commit 並 push 現況、進度檔「未解問題」寫明卡在哪、選項與建議，在 PR 留言（第一行 `[Nebius 回報] v0.1x｜停止｜YYYY-MM-DD`），然後結束。
