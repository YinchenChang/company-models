## 目標
把引擎改成 Oracle 的因果結構（對照表 r1 第 3 節），HTML 與 Excel 數字一致，`verify.sh` 全過。

## 實作原則
1. **雙引擎同步**：新邏輯 Excel 公式與 HTML 引擎兩邊都實作，以 Excel 為準，cmp31 新增比對項涵蓋每個新區塊（同 Nebius v0.1b）。
2. **不刪通用程式**：Oracle 沒有的機制（可轉債有效轉換價、持股、其他事業燒錢等）輸入設 0 或空清單，畫面顯示「不適用」，不刪除通用程式碼。
3. 公司特有內容一律放 `company.json`；新增欄位同步 `scripts/fields_doc.py --write`。新增首期一次性金額或期初餘額時，加入 `calendar_q.py` 的 `ROLL_FIELDS` 並在 `asOf` 標記季度。
4. 改名用 `rename_ids.py`；遵守 `oracle/CLAUDE.md`「勿改」8 條。

## 步驟（每步完成即跑 verify.sh、commit＋push、更新進度檔；verify 未過不得進下一步；每步記錄三情境目標價）
0. 開分支、draft PR、進度檔新增「v0.1b」段落。
1. **欄位搬移與換名**：`oracle` 區段資料搬入既有欄位（`meta`〔company＝Oracle、ticker ORCL〕、`calendar`〔fiscalYearEndMonth 5、latestQuarterFiled FY27Q1〕、`asOf`、`ytdActual`、`historicalPL`、`latestQuarter`、`callFacts`、`debt`、`leases`、`valuation`〔現價取 v0.1a 共識檔最新收盤〕、`quarterly`〔焦點季 FY27Q2，指引取 v0.1a〕、`texts`、`meta.consensusFile`）。刪除 `nebius` 區段（含 fields_doc 說明）。`peers.list`：加入 CRWV、NBIS 與軟體同業（v0.1a 數字），移除 ORCL 本身。畫面文字中描述本公司的 CoreWeave／Nebius 全部換成 Oracle。確認首期長度＝0.75 年、期間標籤 FY27–FY31。
2. **OCI 營收主軸**：`scenarios.mwPath`（期初已交付 MW 取 v0.1a；三情境依對照表 r1 第 4 節第 1 條）、`scenarios.revMW`（11.62／17.40／24.20 或 v0.1a 更新值）、可計費比。**首期校準**：以 Q1 實際 OCI 年化校準期初可計費 MW，爬坡收斂到已交付 MW（Nebius v0.1c 追加的做法），寫明是對齊已實現實際數。RPO 改對照列（含「36 個月轉換一半」說法對照模型 36 個月累計 OCI 營收）。
3. **傳統事業（新）**：SaaS、軟體、服務、硬體四列營收（成長率路徑放 `company.json`，取最近四季年增率逐年收斂到長期值）與合併 EBITDA 率，加入損益 EBITDA 與營運來源。沿用 Nebius「其他事業 EBITDA」機制擴充成多列，或另建區塊，擇一並說明。首期 Q1 實際與模型三季相加須等於 FY27 年度值；與 FY27 指引（≥ $90B）差距 >5% 附差異原因。
4. **客戶出資（預付）**：`defaults.prepay` 改為 Oracle：客戶出資覆蓋比（v0.1a 推得）、認列年數、期初合約負債（10-Q）。若預付在報表上與營收認列關係不明，預設「預付流入抵減淨資本支出、不另認列非現金營收」並在報告說明替代口徑與影響。
5. **股利與融資瀑布**：類現金流量新增「股利」列（每股 × 期初股數）；瀑布：預付 → 現金（高於最低現金）→ 投資級無擔保債（上限：總債務 ≤ 4.0× 當期 EBITDA，票面利率取 v0.1a 最新發行加權）→ 強制轉換特別股／ATM 股權（每年上限＝現市值 5%，發行價沿用模板折價機制）→ 高息債溢出（利率沿用模板）。既有債券到期梯由瀑布再融資。高息債溢出在一頁摘要以一句標示「需失去投資級才能融資的金額」。
6. **強制轉換特別股與既有證券**：用可轉債模組承接強制轉換特別股（一律轉股，轉換比率取下限＝稀釋最大，保守）；股利列入融資成本。不適用的欄位（有效轉換價分類等）照原則 2 處理。
7. **租賃**：既有租賃與尚未起租承諾依 v0.1a 起租時程轉成每期租金；若時程未揭露，以「平均分攤到 FY27–FY30 起租」為預設並列替代。
8. **評價**：WACC 依 v0.1a CAPM 輸入計算並寫入 `valuation`（列出計算式）；EV/EBITDA 腿改分部加總：傳統事業 EBITDA × 軟體同業 NTM 中位數＋OCI EBITDA × 6×（`valuation` 新欄位，錨定 FY29）；DCF、反向 DCF（穩態 EBITDA 率格線改為合併口徑，或維持 OCI 口徑並說明）、季度層、期間滾動、共識對照、一頁摘要全部改用 Oracle 欄位。差距超過 5% 的共識／指引項目附差異原因。
9. **整體 verify 與回報**：`verify.sh` 全過；報告列：三情境目標價與區間、每 MW 3×3 敏感度、客戶出資反向測試（覆蓋比設 0 時的融資缺口、新股、高息債）、投資級上限 3.5×／4.5× 敏感度、OpenAI 容量實現 50%／70% 敏感度、已套用的預設、未解問題。
