# Oracle 收支模型 — 交接檔（v0.2，2026-10-08；評價日 2026-08-31〔FY27Q1 10-Q〕；現價 $144.77〔2026-10-06〕）

## 1. 這是什麼（命題）
Oracle（ORCL）的資金與評價模型，CRWV「Backlog 不是現金」、Nebius「預付款能否讓 backlog 變成現金」之後的第三個對照組。命題：Oracle 用**傳統軟體現金流＋客戶預付＋投資級債＋一次性股權**支應 AI 基礎設施擴張——檢驗在 Tokenomics 正向推導的每 MW 經濟性下，OCI 的 MW × 每 MW 收入能否把 $664B RPO（約一半為 OpenAI）轉成足以支應資本支出、租金與股利、並維持投資級評等的現金，而不需要再發股。

**目前答案**：**融資撐得住，價值撐不住；建設延誤再壓一層。** 三情境都不需新股、不溢出到高息債；v0.2 改用租賃調整後槓桿（(債務＋租賃負債) ÷ (EBITDA＋租金)）後，保守情境最高 4.34×（FY29），離 S&P 降評門檻 4.5× 只剩 0.16×，基準 3.56×、積極 3.14×。但若照 S&P 全額口徑（含尚未起租的約 $171–180bn 租約承諾現值），FY27 保守／基準約 6.2×／5.8×，已超過門檻（需 Andy 決定口徑）。建設延誤（保守 6／基準 3／積極 0 個月）使收入延後、而租金與 GPU 付款不延後：基準目標價少 $10.6、FY28 營收少 $11.2bn、閒置資本峰值 $25.9bn。目標價 保守 $74.0（賣出）／基準 $133.9（中立，較現價低 7.5%）／積極 $226.6（買進）。結論取決於每 MW 年收入與延誤長短；信心中等偏低：每 MW 單價、OpenAI 對手方集中度、租賃口徑是三個主要不確定。

模型同時輸出 HTML（互動、可調輸入）與 Excel（全部活公式），兩者數字必須一致（cmp31 三情境＋錨定 1 各 398 項）。

## 3. 模型結構與因果
**因果主軸**：已連網 MW → 可計費 MW →（v0.2：往後平移建設延誤月數）→ OCI 營收；傳統事業四線 → 營收與 EBITDA；EBITDAR × OCI 營收 − 租金 → OCI EBITDA；營運現金＋客戶預付 − CapEx（成長＋汰換）− 租金 − 利息 − 稅 − 股利 → 融資缺口 → 瀑布（現金 → 投資級無擔保債 → 股權 → 高息債）→ 股數與淨負債 → DCF＋分部 EV/EBITDA → 目標價。

## 8. 已知限制
1. **續約價格衰退未做**（CRWV 尚未做）：公司稱到期續約價 +20%，Tokenomics 預期 GPU 壽命期價格下滑（區間 0.3–1.0，類比 0.42–0.70）；每 MW 年收入五期固定。
2. **租賃口徑與 S&P 不同（v0.2 取代「未計租賃負債」）**：上限已改為租賃調整後槓桿 ≤ 4.5×，但只計已起租租約；S&P 全額口徑（含未起租承諾與無條件採購義務）FY27 約 5.8–6.2×。上限只約束瀑布新債，不強制去槓桿。延誤：預付不退款、罰則條款未揭露（預設 0）、延誤月數為情境常數（不逐站）；(c1) 拆解為反事實。
3. **自帶硬體使每 MW 收入偏低的效果未建模**（覆蓋比合併預付與自帶硬體）。
4. **非 AI 的 OCI 併入 MW 主軸**：OCI 營收含非 AI（一般 IaaS），全部以 MW × 每 MW 驅動；Q1 校準把非 AI 部分折成「可計費 MW」。
5. **實現單價 vs 正向推導單價**：Q1 OCI 年化 29.552 ÷ 評價日已連網 2,543 MW-IT＝11.62，等於保守值、為基準 17.40 的 67%；模型把差距歸為可計費爬坡（時點），若實為長期單價偏低，基準應向保守移動。
6. **季度跳升**：FY27Q4 營收 → FY28Q1 跳升較大（年度總額的季度分配），年度數不受影響。
7. **指引差距**：FY27 毛 CapEx 基準 106.1 高於指引 90–95（保守 90.0 在指引內）；FY27Q2 營收模型高於指引上緣約 1.8%。
8. **未具名站點**占 FY27 已連網約 89%（公司不逐站揭露）。
9. **現金稅口徑**：現金稅不含瀑布新債利息，與損益所得稅略不同（偏保守）。
10. 車隊折舊以期初毛 PP&E 計（CRWV 待辦 6，未做）；機率加權目標價、GPU 批次、5a 精簡、5b 只讀檢視器未做（範圍外）。
11. 共識隱含 OCI 倍數用模型的傳統事業 EBITDA（共識不分部）。
12. LibreOffice 計算模擬運算表會留殘值，`xlx.py` 以兩輪重算處理；Excel 本身不受影響。
13. **「輸入與假設」D 區重複表頭「項目」**（v0.1 起）：該頁 A 欄任何變動都會使 `--vs-dist` 無法以列名稱配對；v0.2 新列因此放在「運營_產能與收入」「各期收支」「資產負債_新債與新股」，上限兩格沿用 v0.1 的 A 欄名稱（說明在 I 欄）。待一次性處理（CLAUDE.md 待辦 2b）。
