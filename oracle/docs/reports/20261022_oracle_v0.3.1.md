## 0. 結論（三句）
1. **目標價小幅上調**：基準 $83.3 → **$84.2**（+0.96）、保守 $76.6 → $77.4、積極 $90.9 → $91.9；三個情境仍全在賣出門檻 $109.8（現價 $129.13 × 85%）以下，評等維持「賣出」。

3. **與共識差距仍大且結論對價格軸敏感**：基準目標價 $84.2 對共識平均目標價 $237.36（S&P，43 家；MarketBeat $249.52，47 家）低 65%；FY27 營收低於共識 8.2%、FY29 低 30.5%（皆為「觀點」或「已知限制」，原因已附）；且 k_長約 由 0.80 升到 Oracle 自身合約 1.47 時，基準容量目標價 $76.0 → $152.6，高端已超過現價——「賣出」是價格軸（長約是否貼近 Oracle 自身合約）的函數，不是三個容量情境的穩健結論。

## 6. 待 Project 判斷事項
1. **價格軸 vs 結論**（最重要）：基準容量下 k_長約 0.80–1.47 的目標價 $76.0–$152.6，高端已超過現價 $129.13；3 × 3 矩陣中「積極 × 價格高」$139.6 亦高於現價。建議：維持預設（k 取外部長約錨 0.89，因 Oracle 自身合約價未經證實），但把「賣出」的措辭限定為「在外部長約錨下」，並以研究方向 (1)(2) 優先查 Oracle–OpenAI 合約口徑（4.5 GW 是 IT 或設施；金額涵蓋項目）。
2. **軟體同業倍數、beta、債務成本**：本次無法更新。建議由能連外的環境（或 Andy 提供 StockAnalysis／MarketScreener 的當日數字）補，再發 v0.3.2；或 FY27Q2 更新（v0.4）時一併處理。預期影響：beta／債務成本更新使目標價上升約 $0.5–1.0（方向：上），同業倍數影響傳統事業估值，方向未知。
3. **FY27 EBITDA 差距 −5.95%**：是否把利潤類的差異原因門檻改成金額差或加一條 5% 比例規則？建議維持現規則（利潤率差 2pt），因金額差來源是營收差（已有原因）。
4. **共識檔來源品質**：MarketScreener 頁面無日期；若 Project 要求 FY27–29 預估須附頁面日期，需重取。
5. **EBITDA 口徑說明**採「差額＝Q1 實際與模型 Q1 之差」純文字；若要列數字（48.85 − 47.63＝1.22），需額外加一列。建議不加（精簡原則）。
