# Oracle v0.4.2 → v0.4.3：Tokenomics 快照換 v21.9（基準不變）

**結論：** 基準數值完全不變：加權目標價 73.22、評等放空、上檔空間 −41.9%（現價 126.06）。Sens 頁只有讀高成本欄的 `he_all` 高一個案例改變：86.05 → 81.34，評等仍是放空。快照由 v21.4 直接跳到 v21.9，但本模型取用的名稱只有高成本欄有變。

## 做了什麼
- **新快照** `data/tokenomics_snapshot_v21.9.json`（`20261103_Tokenomics_v21.9.xlsx`，master 7276259）。
  - 名稱清單取自 v21.4 快照的 42 個名稱，與 `microsoft/data/tokenomics_names.txt` 相同（含 optional 3 個）。v21.4 快照本來就是從 microsoft/data 複製來的。
  - v21.4 與 v21.9 逐名稱比對，結果如下：
    - 高成本欄：`IF_HoldEcon`、`IF_HoldAcct`、`IF_GPUhrEcon`、`IF_DeprLifeIT`、`IF_DeprIT`、`IF_OpexGW`、`IF_MaintIT`，以及 L1 的高端值。
    - `IFC_Use` 的 IF_DeprLifeIT 列，用途文字有改。
    - 基準欄不變。v21.6／v21.7 只改了 TPU、Trainium、AMD 的 NonNV，本模型沒有取用這些名稱。
- **舊檔處理**
  - v21.4 快照移到 `data/_待刪除/`（新建資料夾）。改版後已沒有程式讀它。
  - `data/tokenomics_snapshot_v19.0.json` 保留不動：`scripts/sens_v04.py` 的 OX（營運費用基準 × 0.8／1.2）仍讀它。
  - v0.4.2 成品移到 `dist/_待刪除/`。
  - `data/sens_v04.json` 依本模型慣例原地覆寫。
- **`build_oracle.py`**
  - 新增 `TKV = "v21.9"`。
  - In A1〔v0.4.3〕、D 節標題、he_* 來源、`gh_h100` 來源、Thesis K 欄說明、Sources 第 12 列改由快照取值。
  - In 頁 `life_ai` 說明原本寫死「高成本 4」，改為由快照取值，現為 5。
  - 沒有改任何模型輸入值或判斷。
- **`scripts/sens_v04.py`**：IF_HoldEcon 低／高改讀 v21.9 快照。整套 46 案加 WACC × g 格重跑。
- **`make_v04.sh`**：產出 `dist/20261104_Oracle個股模型_v0.4.3.xlsx`／`.html`。
