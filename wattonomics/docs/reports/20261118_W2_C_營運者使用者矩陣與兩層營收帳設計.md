# 營運者 × 使用者矩陣延伸與兩層營收帳（設計與資料盤點；2026-11-18；第二波 Wattonomics 報告 C）

**性質：** 只出設計與資料盤點，不建置、不改模型。依據：規則 v1.5 草案 C8 對帳點 (b)（草案，Andy 尚未逐條核可）；Andy「原則上同意」AI 營收池兩層並列（擁有者層、使用者層）、層內加總、跨層不相加。

## 結論

1. **現有矩陣只能當骨架，不能直接掛營收：** Matrix 頁只有 2025、2026、2027 三個**年底** IT GW，沒有年平均；列和讀 Players 頁（站點證據路徑），2026–2027 列和合計 37.12／49.35 GW，**不等於主路徑 `WIF_MktGW_YE`（44.86／70.36）**；沒有任何 `WIF_` 名稱輸出；「未分配」占 2026 年 35%（12.99 GW）、2027 年 40%（19.73 GW）。
2. **兩本帳需要的資料，公開等級差很多：** 擁有者層有 [Verified] 的只有純 AI 雲（CoreWeave、Nebius、WhiteFiber、IREN 等新雲）與 xAI（SpaceX 424B4 分部）；三大雲與 Oracle 只有含非 AI 的分部營收。使用者層只有 OpenAI、Anthropic 有營收數字，且為 [Interested-party]；Meta、Google、Amazon、Microsoft 的終端 AI 營收不揭露。**自用（2027 年 21.5 GW，含中國 13.7）與未分配（19.7 GW）兩格明列為缺口，不設算影子營收。**
3. **年底 GW 換年平均：首選「兩期年底平均」**（與現有 `WIF_MktGW_Avg` 同法、成本最低）；次佳「Pipeline 逐站上線月加權」；第三「季報實際上線電力插值」（只少數營運者有）。
4. 需 chat 端／Andy 先決定的兩件事：(a) 矩陣列和改對主路徑還是維持站點路徑（改主路徑則「未分配」更大）；(b) 營收帳放 Wattonomics 還是 Tokenomics（Tokenomics 是「每 GW 營收」權威；Wattonomics 只放 GW 與分配，營收單價讀 Tokenomics 較合三層分工）。

## 2. 兩本帳的設計

**原則：** 兩層並列；擁有者層內可加總、使用者層內可加總；**跨層不相加**（擁有者的租金是使用者的成本，相加會重複）。自用與未分配列出 GW、營收欄寫「缺口」，不設算。

### 2.1 擁有者層（租金／雲端算力營收）

每格（營運者 × 使用者，使用者≠自用）：

| 欄位 | 說明 |
|---|---|
| `gw_ye`、`gw_avg` | 年底、年平均 IT GW（第 3 節） |
| `form` | 租用型態：裸機／GPU 雲（按 GPU 時）、機房託管（powered shell）、受管服務 |
| `rent_gwyr` | 每 GW‧年租金（US$B），標記與來源；機房託管與 GPU 雲差一個數量級，必須分開 |
| `rev_owner` | ＝ `gw_avg × rent_gwyr`（設算）或公司揭露營收（實績優先） |
| `contract_ref` | 合約總額、年限、起租時點（例：Microsoft–Nebius、Oracle–OpenAI、CoreWeave–OpenAI） |
| `tag`、`src` | 五級標記與來源 ID |

列加總＝營運者的 AI 租賃營收；對帳點：與公司揭露營收比（C8 (b)）。

### 2.2 使用者層（終端 AI 營收）

每欄（使用者）：

| 欄位 | 說明 |
|---|---|
| `gw_avg_used` | 該使用者使用的年平均 GW（欄和，含自建＋租用） |
| `rev_user` | 終端 AI 營收（訂閱＋API＋企業），註明總額或淨額（OpenAI 對 Microsoft 分成） |
| `rev_per_gw` | ＝ rev_user ÷ gw_avg_used（Derived；對照 Tokenomics 每 GW 營收） |
| `fy_map` | 財年對曆年換算 |
| `tag`、`src` | 同上 |

欄加總＝市場終端 AI 營收（只含有揭露者）；與擁有者層並列、不相加。

## 4. 年底 GW 換年平均的方法

| 序位 | 方法 | 證據強度 | 成本 | 不選或限制 |
|---|---|---|---|---|
| **首選** | 兩期年底平均：`gw_avg_t ＝（gw_ye_{t−1}＋gw_ye_t）÷ 2`（線性爬坡） | [Assumed]（線性）；與現有 `WIF_MktGW_Avg`（2025 15.89 ＝（6.21＋25.57）÷ 2）同法，兩本帳與市場總量一致 | 最低：每格一個公式；需補 2024 年底欄（目前矩陣無） | 下半年集中上線時高估年平均 |
| 次佳 | Pipeline 逐站上線月加權：每站 MW ×（12 − 上線月＋1）÷ 12，再依營運者 × 使用者加總 | 公司公告時程＋已確認延遲（Interested-party），與基準同源 | 中：要把 Pipeline 站點對到 T1 的使用者，未對到的仍用首選 | 站點路徑只覆蓋部分 GW（2027 站點 49.35 對主路徑 70.36） |
| 第三 | 季報實際上線電力插值（CoreWeave、Nebius 等季報 active power） | Verified，最強 | 高：逐家逐季，且只有少數營運者揭露 | 覆蓋太少，只能作校驗 |

## 5. 待 chat 端／Andy 判斷
