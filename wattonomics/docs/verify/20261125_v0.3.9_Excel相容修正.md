## 1. 原因

| 現象 | 原因 | 修正 |
|---|---|---|
| Deploy 主路徑 2026–2029 及下游 #VALUE! | CapexGW「已知值累計個數」首欄（2023）公式 `=(X<>"")` 結果是邏輯值。Excel 比較時邏輯值恆大於數字，次欄 `IF(前一欄>0, 前一年補值×(1+g), "")` 在 Excel 判為真，拿空字串去乘 → #VALUE!。只有 2023、2024 兩年都無資本支出值的 Oracle、CoreWeave、Nebius 中招；經廠房提前入帳（t−2）傳到 2026 年起的主路徑 | 首欄改 `=(X<>"")*1`（`builder/build.py`） |
| 開檔出現修復視窗「Removed Records: Formula from /xl/worksheets/sheet21.xml」 | Checks G-K2 單格公式約 8,600 字元，超過 Excel 上限 8,192 | 拆成逐家小計（Checks 該列 J 欄起，一家一欄），C 欄 `SUM` |

## 2. 建置

```bash
python3 wattonomics/builder/build.py --base <原 v0.3.9.xlsx> --version v0.3.9 --date 20261119 --out build/raw/20261119_Wattonomics_v0.3.9.xlsx
soffice --headless --calc --convert-to xlsx:"Calc MS Excel 2007 XML" --outdir wattonomics/model build/raw/20261119_Wattonomics_v0.3.9.xlsx
python3 wattonomics/tools/export_snapshot.py …；python3 wattonomics/tools/export_explorer.py …；python3 siliconomics/tools/export_baseline_status.py
```
