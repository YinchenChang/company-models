# Oracle 2028 園區 GW 與資本支出推得 GW 差異診斷（2026-11-04）

- 問題（Andy 2026-11-04）：「它 2028 年的園區合計 4.91 GW，但由資本支出推得只有 1.24 GW」——是只承擔部分（土地廠房用租賃、客戶預付），還是期間錯配（資本支出只算錢，沒有涵蓋完整所需）？
- 範圍：只診斷，不改任何模型。對象為 `wattonomics/model/20261102_Wattonomics_v0.1.9.xlsx`（main）與 `oracle/dist/20261030_Oracle個股模型_v0.4.2.xlsx`。
- 附件：同名 `.xlsx`（輸入、分期、甲2 逐變體重算 23 組、橋接、敏感度、核對；全部為公式，LibreOffice 重算，錯誤格 0）；證據清單 `wattonomics/evidence_raw/E_oracle_20261104.md`（E#1–E#20）。
- 單位：IT GW（設施 ÷ IF_FacilityGW 1.2）；金額十億美元。

## 結論先講

1. **4.91 與 1.24 都是「2028 年新增」，口徑相同；但這個比較放大了差距。** 4.91 中有 4.85 GW 是四個整站在 2028 年 11–12 月一次上線（園區清單只有完工月）。改看年底存量，差距是 8.61 對 4.87（差 3.73），幾乎等於年新增的差（3.68）。
2. **同口徑（年底存量）看，主因是「只承擔部分」：** 承租園區的廠房由房東出資，Oracle 資本支出只買 IT，但甲2 用「IT＋廠房」全額成本換算，占差距約一半（1.87 GW，區間 1.66–2.10）。其次是 AI 占比與每 GW 成本組合（合計 1.01 GW）。
3. **「期間錯配」分兩種，結果不同：**
   - 資本支出到上線的時差（你問的那一種）：很小。年新增 0.18 GW，年底存量約 0。個股模型 Y9 的 FY27–FY28 高峰、FY29 下降，與 Oracle Investor Day（2026-10-28）的說法一致，不是 Y9 漏了 2027 年的錢。
   - 園區清單把整站放在完工月：只影響年新增（1.67 GW，區間 0.14–2.43），不影響年底存量。這是園區端的時點問題，不是資本支出端的問題。
4. 仍有約 0.85–0.88 GW 未解釋，最可能是客戶自帶硬體與供應商融資（Oracle 已說會用，未揭露金額）。

## 五、判斷

**判斷：** 同口徑（年底存量）比較時，差距主要來自「只承擔部分」——Oracle 承租的園區廠房由房東出資，Oracle 的資本支出只買 IT 設備，而甲2 用含廠房的全額成本換算。這一項占 50%（1.87 GW，區間 1.66–2.10）。你問的「期間錯配」（資本支出時差、Y9 缺 2027 年的錢）影響很小。4.91 對 1.24 看起來特別大，主要是園區清單把四個整站放在 2028 年 11–12 月；這只影響年新增，不影響存量。

**信心：** 只承擔部分為主因——中高（兩個管理層來源、租賃承諾、三項獨立數字檢查都指向同一方向；承租比例本身沒有揭露）。年新增的分期效果——中（R 12–24 月的區間很寬）。殘差 0.85–0.88 的來源——低（客戶自帶硬體金額未揭露）。

**判斷失效條件：**

1. Oracle 10-Q 揭露 PP&E 增加中，土地與建物占資本支出兩成以上 → L 小於 0.8，A1 縮小，需重估。
2. FY27Q2（2026-12-10 財報）每季交付掉到 0.5 GW-IT 以下，但季資本支出仍在 250 億左右 → 每 GW 實際成本高於只 IT，A1 不足以解釋。
3. Jupiter、Port Washington、Saline 確認首棟要到 2028 下半年才交付 → 分期效果縮小，2028 年新增的差距回到資本支出端，此時才需要檢討 Y9 2028 年的金額。
4. Oracle FY29 資本支出遠高於 Y9 的 38（例如接近共識 85）→ 表示有清單外的新站點，不是時差。
